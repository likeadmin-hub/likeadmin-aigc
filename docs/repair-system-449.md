# 1.0.448 升级 1.0.449 在 76% 中断的恢复步骤

适用范围为使用标准站点目录更新、当前仍为 1.0.448、已下载原始 1.0.449 ZIP 的站点。故障表现为下载和验签均成功，写入更新时提示“新迁移不支持会话变量或动态 SQL”。推荐模型的动态列迁移和租户溢价权限的多表语句均与该版本执行器不兼容。

## 操作前

1. 在维护窗口备份当前数据库、站点文件及 runtime 中的更新包、更新回执和日志。记录首次失败的任务 ID。暂停接收新请求，等待正在运行的作业完成，再停止本站的常驻进程。
2. 把修复工具包解压到站点以外的维护目录，核对交付方提供的工具包 SHA-256。准备好已下载的原始 1.0.449 ZIP，在下面的命令中填写实际站点目录和 ZIP 路径。使用本站文件所有者身份及本站 PHP 8.2 CLI 执行。
3. 修复工具会核对原始 ZIP、当前版本、升级器文件、首次失败任务及回执。遇到“执行器与基线不一致”“回执与首次故障不符”或锁冲突时，保留现场并核对对应提示。请勿手动清除回执或修改版本号。

## 先预览，再接入修复

从解压后的工具目录执行。宝塔安装的 PHP 8.2 CLI 常见路径为 `/www/server/php/82/bin/php`。

```sh
SITE=/实际站点目录
ARCHIVE=/实际保存路径/system_1.0.449.zip
PHP=/www/server/php/82/bin/php
"$PHP" scripts/repair-system-449.php --site="$SITE" --archive="$ARCHIVE"
"$PHP" scripts/repair-system-449.php --site="$SITE" --archive="$ARCHIVE" --apply
```

预览返回 `mode=preview`。接入成功后返回 `mode=applied` 及备份目录。此时站点版本仍应为 1.0.448。工具只为原始签名包中的四份已知 SQL 选择校验过的静态 SQL，其中两份修正表前缀。原始程序会先规划所有系统 SQL，再执行第一条。对于能证明在规划阶段失败的原始任务，工具将已回滚回执从 running 改回 pending，并保留原回执。所有 SQL 随后由正式升级器按正常阶段执行。

## 恢复升级与验收

1. 若 PHP-FPM 配置禁止自动检测代码变更，在维护窗口内让本站 PHP 工作进程重新加载代码。
2. 在平台端「系统服务 → 版本更新」重试已下载的 1.0.449。升级器仍会复核包、签名和站点授权。分发暂停期间，如果页面没有可用入口，或站点的下载授权已过期，请停在此处，待该站具备正式授权及更新入口后再继续。
3. 以更新控制台显示完成、系统版本为 1.0.449、后台有成功的更新任务记录为准。检查平台和租户的「任务日志 → 数据统计」、算力商城的模型推荐及租户列表的溢价权限。按控制台提示重启本站常驻进程，恢复访问。
4. 如升级过程中出现其他错误，保留新任务 ID、原始签名 ZIP、备份目录和回执。对于尚未重试的站点，恢复接入前备份可退回原始失败现场。开始正式升级后的恢复应使用同一备份时间点的数据库和站点文件。

本工具仅供站点维护人员处理这个特定版本故障。原始签名包及私有版本分发状态均由正式发布系统管理。
