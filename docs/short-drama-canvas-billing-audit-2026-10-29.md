# 短剧、画布与Agent费用审计及优化方案（用户承担）

日期：2026-10-29。最新用户约束：**所有实际模型费用由用户承担；取消所有人为累计预算和次数封顶；保留现有业务流程、生成方法、价格与结算方式。** 此前关于租户补贴、承担方配置和到预算即暂停的建议全部撤回。本次仅修订文档，没有改源码、账目或数据库，没有付费调用。

## 1. 证据与实施边界

源码审计覆盖短剧、短剧画布、独立画布、Agent、共享文本/图片运行时、PointService与前端费用展示。静态调用链可证明当前收费与状态行为，不等于已实测供应商扣费。此前本地只读聚合可能包含fixture，不能视为真实付费验收。

本方案不新增预算服务、用户/租户承担切换、收费步骤或补贴模式。普通用户按现有租户零售价付费，租户按现有平台成本付费，两套金额独立。用户承担并不意味着取消租户平台成本账，也不允许叠加向租户扣一次用户零售价。

租户后台管理者自用的userId=0专用功能保持原业务；不能冒用后台身份让普通用户免费，也不能为落实本次需求给原本没有用户身份的后台工具伪造扣费用户。

## 3. 每一步收费说明

| 原有环节 | 用户费用规则 | 必须展示/保存的依据 |
| --- | --- | --- |
| 编辑、保存、选择模型/素材、上传登记 | 原本无模型费用的继续免费 | 不制造生成消费记录；存储政策保持原业务 |
| 故事、全剧节奏、分集大纲、剧本、分镜文本 | 按实际模型调用与usage向用户结算 | 阶段、模型、消费编号、用量、已扣和待用量状态 |
| 引用图片理解/角色场景描述 | 独立文本调用由用户承担 | 不藏在“免费编辑”中，原费用区域说明 |
| 格式修复、提示词优化、内部路由 | 确实新增模型调用时用户承担；本地适配不收费 | purpose及父任务/阶段关联，真实用量与原价格 |
| Agent规划、工具循环、长资料读取 | 文本逐次真实结算，媒体工具按原方式另计 | 同一run汇总，阶段明细可查；不设金额或次数总封顶 |
| 角色、场景、三视图、分镜图片 | 原固定价预占或实际用量结算 | 数量、规格、模型渠道、应付/预占/已扣/退回 |
| 视频、配音、BGM、转写 | 沿用原报价、确认与提交方式 | 原媒体任务、上游受理、结果与账目关联 |
| 同一received回包读取、确定性解析/继承 | 没有新模型调用，不新扣费 | 保留原消费引用，不伪造新的请求 |
| 已有素材复用 | 不重新生成，不新扣生成费 | 原资产和原版本引用 |
| 本地合成/ZIP导出 | 保持原0点 | 失败只恢复合成/导出，不再次生成媒体 |
| 结果或用量不确定 | 保留待核对，不能直接视为免费或全退 | 原任务、回执、usage、两侧流水；核对后结算/释放 |

预估金额用于让用户理解费用，不是任务停止预算；不得因累计费用超过预估、累计Token较多、修复次数较多而失败。真实余额不足沿原规则处理；充值后仍能恢复原任务，已完成内容与原账目保留。

## 4. 预算和次数封顶处理

必须清除的范围包括：

1. 项目、任务、阶段、正文、修复、复核、Agent累计金额/点数和Token封顶。
2. 按总调用、修复、资料读取或重试次数达到固定值停止的分支。
3. 历史preferences.budget、默认预算、前端停止提示及兼容分支中仍生效的累计限制。
4. “预算已达上限”“次数已用完”“操作较多请缩小范围”等由内部计数造成的终态。
5. 单轮dispatch到限后，业务应继续排队处理，不能误记失败/取消或强迫新建任务。

保留真实模型单次能力、供应商限流与规格、实际余额、权限、归属、结果受理核对和幂等；这些不是内部消费预算。取消次数封顶也不能无变化重复提交同一付费请求；使用既有检查点与缺陷定位继续处理，传输不确定先查询原请求。

消费记录中的金额、Token和次数可以累计统计，它们仅用于账单、审计和进度，不能反过来成为停止条件。

## 5. 不改变现有业务的费用优化步骤

1. 列出现有所有创作入口及实际收费动作，逐项关联purpose、项目、任务、阶段、媒体版本和消费编号。
2. 保持原价格、用户身份、零售价/成本价快照及资金服务；不增加payer配置或给共享SKU改价。
3. 在原报价与费用说明中包含可能的辅助文本调用；在现有账单位置显示真实分项，不能悄悄把多次调用假装成一次固定价。
4. 将能本地完成的校验和合法适配提前，避免明知媒体不可用还先产生辅助调用；不改创作方法、不引入额外模型调用。
5. 复用已有generation_spend和Agent calls，回查权威消费状态，避免只看父任务状态导致漏账。
6. 补齐预占、结算、退款、待用量、待核对的展示映射，费用异常沿原恢复方式处理。
7. 校验旧任务、重复callback、刷新、断线、重试、用户取消和导出恢复，保证业务与账目兼容。

是否需要补充持久化引用字段，要先检查现有JSON/关联表；方案阶段不执行SQL。任何实际新增字段都按原安装/升级/回滚流程办理。

## 6. 必须保留的资金与任务保护

- 原工具规范参数去重与提交锁，防止同一方案重复保存或提交。
- 原有手动/自动模式授权和价格变化重新确认，不删除已有节点，也不为预算新增节点。
- 原received回执持久保存、校验结果关联、本地重放不再次提交。
- 原不确定running请求核对；连接建立前失败与读超时受理不明分别处理。
- 原价格快照、实际usage、共享PointService、两侧资金流水、退款/释放与幂等。
- 历史消息恢复不能自动执行过去未完成的收费动作；用户取消仍停止后续未提交动作。
- 权限与资产归属、所选模型身份、规格及内容版本，不因费用由用户承担就放宽。

按用户最新要求取消的是人为累计停止线，不是上述原有业务保护。
