# 短剧生成系统重构：产品方案、执行规格与验收记录

日期：2026-10-09。任务分支：server/web `feature/aigc-upgrade`。
状态：执行中。本文既是产品规格，也是后续实施和排障的交接依据；未勾选的验收项不能称为已完成。

## 1. 目标与事实边界

目标是在保留「输入 → 故事设定 → 分集大纲 → 单集剧本 → 主体/场景 → 分镜图/视频」主流程的前提下，提高内容完整、可恢复、可制作的成功率。不能以关闭质检、吞掉错误、删除对白、把未核验标记为通过换取成功。

本次检查不是只针对一个失败任务。现有代码同时包含整集生成、定时骨架、逐场展开、内容验收、连续性复核及其各自修复循环。主要系统性矛盾：

1. 定时骨架在对白出现前锁定镜头数、每镜秒数与唯一地点；正文需要转场或对白变长时被结构校验拒绝，无法进入后续时间再分配。
2. 时间码、明确总长、约定时长和系统默认时长混用。系统计划被当作用户硬约束；生成与审核读取规则不完全一致。
3. 多层 LLM 复核重复理解原文，格式修复、内容修复、连续性修复预算叠加；一轮修复可能破坏另一轮的结果。
4. 上传文本、创意生成、局部修改和既有素材各有不同的保留要求，不能统一成「不允许改任何字符」或「全部可重写」。
5. 前端状态、后台任务、已保存候选、已通过剧本和制作素材需要区别；页面重开应恢复任务快照，而非重新提交。

证据：项目3809第1集在质检开启情况下完成；第2集骨架将廊下动作放入大厅 beat，正文正确引用已登记的花廊却被 assertPart 拒绝。此例说明有系统约束冲突，不能归因为模型容量不足。它不是本方案唯一依据。

## 2. 不变原则

- 租户、用户、项目授权隔离保持不变；所有上游调用走现有市场与计费服务。
- 同一个任务、阶段、输入版本的已付费返回先保存再解析；网络不确定不得自动当作未提交重发。
- 任何候选失败不覆盖已验收版本；旧媒体和用户修改保留。
- 新规则带版本，新建任务使用新版本；旧任务继续使用冻结版本，不修改其已提交的上下文。
- ID 是关联键，显示序号不是 ID。重排不换实体身份；拆镜记录父镜头。
- 用户明确要求优先，系统初步安排允许调整。不得虚构用户限制。
- 不动 AIGC 其他应用内容、主题及共享市场协议；不发布版本包。

## 3. 产品流程与输入分类

| 输入 | 初步处理 | 生成边界 |
| --- | --- | --- |
| 一句话灵感 | 补充故事设定，多集确认后生成大纲 | 可创作新对白和合理过场 |
| 详细梗概 | 提取已有事件、人物与限制 | 不改变核心事件；补足表达 |
| 小说/长文本 | 保留全文与来源分段，确定改编范围 | 不把全文硬塞进一次模型调用 |
| 已分集剧本 | 保留原集号、边界、台词与剧情 | 默认忠实拆镜，不重写故事 |
| 已有分镜脚本 | 映射结构与引用 | 仅补缺失制作信息 |
| 修改请求 | 解析目标和新版本 | 未选中内容、用户锁定文字与素材保持 |

上传仅保存文件。点击发送才启动解析；解析结果保存并可见，然后自动继续画布创作，不要求重复发送。100集文件选择前5集不等于把100集压缩为5集；改编压缩必须是用户明确要求。

多集确认点：故事设定、分集大纲。已完整上传的剧本沿用导入确认流程，不强迫用户重新创作。内部格式修复、引用整理和可行的时间调整不弹确认。

传统入口与画布复用同一剧本核心。画布保持同一项目，每集对应一个页面；共享人物和场景身份。已有逐集制作模式维持「当前集制作完成后提示下一集」，脚本队列的完成不等同于视频完成。批量脚本推进使用既有分集队列，不通过偷偷跳过画布制作阶段实现。

## 4. 单一规则契约

新输入契约升级，任务快照记录版本。后续生成、质检、修复均读取同一 request 快照。

| 规则类别 | 示例 | 行为 |
| --- | --- | --- |
| 用户硬约束 | 只允许两名角色、指定事件、精确60秒、指定台词 | 不能自动放宽 |
| 用户软目标 | 约60秒、温暖、节奏紧凑 | 时间默认±10%；审美建议不阻断 |
| 系统安排 | 初稿镜头数、beat 地点、预估秒数 | 允许调整，但必须引用有效主体/场景 |
| 锁定内容 | 上传原文、用户已编辑台词、已有媒体 | 保留；冲突时展示具体原因 |

无时长要求按内容自然结束，不补空镜凑120秒。明确时间码仍保留原边界。约时长不能影响用户另外明确指定的时间码或精确选择。单镜建议最短时间不作为所有内容的硬门槛；视频模型支持时长属于制作阶段能力，不能反向篡改剧本。

实际对白预计超过14秒时拆分；拆点优先发言轮次、句子、动作反应。每个片段仍需符合所选生产模型的时长能力。不得只改数字假装对白变短。角色标签不计入语音时长；旁白、英文和中文区别估计。

原始剧本台词默认锁定；新创作台词可在本集内容生成阶段按总时间预算精简，但不删除必需事件和用户指定原话。成稿时间修复不擅自删词。

## 5. 新单集引擎

### 5.1 内容先行

1. 生成内容骨架：故事摘要、实际人物/道具、实际地点、有序事件单元，每单元含目标、开场/结束状态、关键事件。此时不固定镜头数、逐镜秒数。
2. 按事件单元展开可拍摄正文和分镜。一个单元可以包含多个已登记地点；地点变化不等于输出错误。发言者必须登记，背景路人不必全部建人物资产。
3. 服务端分配稳定镜头 ID，接受模型在单元内按内容决定镜头数。校验有效引用、非空画面、对白结构、正数时长，不要求照抄初步地点或预估数量。
4. 每个完整单元立即保存候选快照，后续单元失败保留前面的结果；再次执行利用阶段收据重放。
5. 整集对白拆分和时间编排；时间可从其他场次借用，完整内容与明确总长同时不可行时返回具体容量冲突。
6. 最后才进行内容验收和连续性检查，再派生图片/视频提示词。

阶段输出结构：
- 骨架 `{title, story_outline, script_lines, subjects:[{id,name,...}], locations:[{id,name,...}], art_style, scene_beats:[{goal,entry,exit,key_events,scene_ref_id}]}`。
- 正文单元 `{storyboard:[{scene_ref_id,subject_ref_ids,visual_description,dialogue,voice_role,speech_type,recommended_duration_seconds,...}], subjects?:[新增实际主体], locations?:[新增实际地点]}`。
- 禁止覆盖已登记实体；新增实体必须唯一、完整，已有引用必须存在。闭合角色限制交给共享用户要求审核，不能把所有故事一律禁止新增人物。
- 服务端镜头 ID `u{单元序号}_s{镜头序号}`；模型分配的临时 ID 不作为资产身份。

短单集不强制大规模拆分，长内容按事件单元控制调用体积。模型输出截断只缩小当前未完成单元；不得静默只保留前半集。历史带明确时间码任务继续走专用时间码对齐路径。

### 5.2 时间处理

骨架看到整集预算，用它控制内容密度，但不先锁死分镜。每个单元得到剩余预算和已有摘要，避免每单元都当作完整一集。最终用实际对白估计下限并排时长。可行区间内计算纠偏由代码完成；只有镜头内容/剪辑语义需要模型。

故障分类：单镜对白过长→拆镜；整集对白下限超总长→明确内容容量冲突；模型输出格式→局部结构修复；引用缺失→补登记或定点修复；上游超时→任务恢复，不整集重写。

## 6. 质检与预算

基础结构、引用、时间检查始终启用。质检开关控制深度语义核验；开启不能把风格偏好升级为硬约束，关闭也不意味着结构错误可发布。

用户要求提取应尽早提供给生成，并在同任务内复用，保存原文证据。语义问题必须指出要求、镜头和字段，不得凭摘要推测当前分段漏演未到的情节。通用实体分类不应对每轮成稿重复执行。

保留已验证的内容覆盖和连续性证据协议；本次先统一输入与预算，不能为了减少调用直接删掉成熟核验。正文结构修复及语义修复都有上限，正常内容不进入修复环。后续合并重复审查必须以回归结果证明不丢检测能力。

候选状态区分：生成中、基础检查通过、深度核验中、可制作、需修复、上游异常、取消。未核验不显示已核验；已知硬缺陷不发布。上游审核暂不可用保留草稿，不能降级成已通过。旧状态枚举保持兼容，通过附加诊断和友好文案解释失败位置。

## 7. 恢复、版本和长篇

- 收据键包含阶段和输入签名；相同输入返回复用。不同输入必须新版本，不能覆盖旧收据。
- worker 租约/围栏与服务端队列负责生命周期；页面关闭不取消。前端重开读取任务与候选，不重新发生成请求。
- 只有验收成功集进入叙事记忆。事实带来源；下一集读取故事设定、当前集大纲、前集摘要与相关状态，不累计500集全文。
- 道具持有、信息知晓、场景状态、承诺/伏笔是叙事状态；不能凭摘要生成不存在的事实。
- 500集验收先测有界上下文与队列恢复。模拟500集不等同于500集真实生成成功。
- 局部修改只失效受影响提示词/素材，其他媒体保留。整集剧情改动可能需要重新核验后续依赖，但不能自动重做全部视频。

## 8. 制作与资产复用

剧本就绪、素材就绪、成片完成分别计算。主体/场景按身份和版本复用，已有三视图可填充；提示词改写不应误认为新角色，但外观设定变化不可误用旧图。用户第一集选的模型作为项目默认，后续集继承，可单集覆盖。

图片和视频提示词从同一分镜派生；多角色对白按顺序放在视频声音段。图片生成不负责说台词。媒体失败只影响对应媒体任务，不清空剧本。生成前检查模型支持时长、画幅、声音及引用数量，计费与实际选项一致。

## 9. 实施批次与验收

A. 文档和兼容契约：保存本文件；锁定新规则版本，旧任务不改上下文。
B. 内容先行引擎：新任务不再绑定初步镜头数、地点、秒数；保留单元快照、引用检查与全局时长修复。
C. 时间和核验：约时长识别、实际对白估计、固定时长可行性、明确失败说明；保留原文与核验依据。
D. 产品整合：前端展示阶段/恢复说明；共享核心两入口走通；不改画布页面组织和已授权逐集制作节奏。
E. 回归与实测：基础/质量开启、文本/上传、单集/多集、旧任务兼容、重开恢复、上游失败、局部修改；完成后更新下面记录。

关键测试（必须有行为断言，不仅搜索代码字符串）：
- [ ] 同单元大厅→花廊允许，未知地点仍拒绝。
- [ ] 模型自行拆成不同数量的镜头可接受，ID仍唯一且稳定。
- [ ] 角色新增登记后可引用，已有角色不能被覆盖。
- [ ] 一单元失败保留此前快照；重试不重复追加。
- [ ] 精确60秒仍精确；约60秒为54–66秒；时间码不被放宽。
- [ ] 超14秒拆镜，完整对白及顺序保留；整体不可行给出具体原因。
- [ ] 旧v8任务与时间码任务保持旧协议；局部修改不进入全量生成。
- [ ] 质检开/关均不能绕过有效引用与时长检查。
- [ ] 真实质量开启多集完成；记录请求数、耗时、自动修复与未通过项。
- [ ] 两入口共享核心；前端切页读取状态不重复提交。
