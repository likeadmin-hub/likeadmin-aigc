# 平台按租户设置算力溢价 · 开发方案

**交付目标**　平台管理员从「租户列表 → 更多 → 设置算力溢价」为一个租户调整商城供货价。这个租户看到的进货价、发起调用时预占的金额、最终租户账单使用同一套规则。管理员可以留在当前页连续设置不同租户。

**实现状态**　平台端和服务端已在本地实现。平台标准供货价、租户专属倍率、租户零售规则依次生效。数据库迁移和验收入口见文末。

## 一、价格归属与业务范围

| 价格 | 谁决定 | 谁使用 |
| --- | --- | --- |
| 上游成本 | 上游按商品、规格或计费分项提供 | 平台核算成本 |
| 平台标准供货价 | 平台商城现有全局、商品、SKU 或分项定价 | 平台查看基价，作为计算各租户进货价的起点 |
| 租户实际进货价 | 平台为指定租户设置一个溢价率 | 租户后台进货价、毛利、余额预检、预占、实际扣费与对账 |
| 客户售价 | 租户已有零售规则及应用售价策略 | PC、H5、小程序和开放 API 对客户报价、扣费 |

首版以租户为设置单位，覆盖该租户通过算力商城计价的模型和应用 API，包括以后同步进来的规格。平台自营按现有标准价计算。充值面额、会员包价、算力包售价及独立于商城结算的业务沿用各自的定价流程。上下架、推荐、特惠、加入 API 调用等设置继续按原有字段执行，标签本身不参与算价。

### 计算顺序

1. 解析平台规则取得标准供货单价。普通规格沿用 SKU、商品、全局的既有优先级，专用分项沿用各自规则。
2. **租户实际进货单价 = 平台标准供货单价 ×（1 + 租户溢价百分数 ÷ 100）**。建议百分数保留两位，首版只支持非负溢价。默认 0%，恢复标准价即恢复到 0%。数值必须符合存储上限，且产生的单价必须通过现有价格范围校验。
3. 将实际进货价传给已有租户零售规则。跟随价直接继承，固定加价和百分比加价使用新的进货价作为基数，手动售价保留原值。应用已配置的独立售价继续生效，含显式免费；应用跟随商城时取商城的客户售价。
4. 按原计费单位和真实用量结算。单价计算使用十进制定点数，沿用 `MarketPricePolicy::amount` 的六位精度，账单总额使用各现有结算器的精度。倍率只在单价层应用一次。

例如标准价为 10 算力/张，租户 A 使用默认值，租户 B 设置 +20%。两家的进货价分别为 10 和 12。若 B 再设置零售加价 25%，客户价为 15；生成两张时租户扣 24、客户扣 30。若该应用明确设置用户免费，同样两张租户扣 24、客户扣 0。

## 二、平台端交互

- 在「更多」的「调整算力」下增加菜单项。打开沿用租户列表现有弹窗样式，标题显示「设置算力溢价 · 租户名称」，同时显示租户编号。管理员能核对对象，避免给同名租户改价。
- 显示当前规则，提供「使用平台标准价」「按百分比溢价」两项和百分比输入框。输入 20 表示加价 20%。恢复标准价走相同的预览和保存流程。
- 点击「预览影响」展示真实商品和规格，列出单位、当前及拟生效进货价、客户售价。汇总影响的 SKU 数、冲突数；样例优先展示冲突，完整冲突支持分页。分项计价展示到具体费率，如“每百万输出 Token”，以免被一个“起价”掩盖。
- **冲突处理**：对当前可售的商城手动售价，逐项检查。此次调整引起或加重的倒挂阻止保存，并指出需要调整的租户零售价及最低可用值。既有冲突单列；降价、恢复标准价等改善操作可执行。未上架规格在预览中提示，上架时再做有效性校验。应用明确设置的独立售价、免费或补贴策略显示影响提示，仍按该应用原有策略处理。
- 预览后修改数值须重新预览。保存中锁定当前弹窗的提交按钮。成功时根据响应只更新目标租户行，保留页码、搜索条件、滚动位置；失败时保留输入并显示原因。已配置的行在租户名称下显示「算力溢价 +20%」。默认行保持简洁。

## 三、数据与接口

### 存储和兼容

建议新增 `tenant_power_supply_markup`，每租户一条。现有商城的 `power_market_price_rule.owner_id` 已分别表达平台标准规则和租户零售规则，独立存储能让平台供货调价和租户零售调价各自保存、授权和恢复。

| 字段 | 建议类型及约定 |
| --- | --- |
| tenant_id | 与租户主键同型，唯一键 |
| rate_percent | DECIMAL(9,2)，非负，保存百分数本身 |
| revision | 无符号整数，有效变更递增 |
| updated_by、update_time | 平台管理员 ID、服务端生效时间 |

缺行读取为 0%、版本 0，升级无需回填全部租户。第一次有效变更创建记录；恢复为 0% 后保留版本，防止旧预览覆盖新操作。金额与百分比在接口中使用十进制字符串。规则变更同事务写入可追溯的价格变更记录，包含租户、操作者、前后费率、版本、时间、请求标识。普通系统日志支持清空，因此业务调价记录和账单快照必须可独立追溯。

### 建议接口

遵循现有平台端接口前缀及响应封装。三个接口均校验平台管理员身份、权限和目标租户，客户端只提交租户、拟定规则或预览凭据。金额由服务端计算。

| 平台端操作 | 参数 | 返回及语义 |
| --- | --- | --- |
| GET `tenant.tenant/supplyMarkup` | tenant_id | 当前费率、版本、最近修改人和时间 |
| POST `tenant.tenant/previewSupplyMarkup` | tenant_id、rate_percent、expected_revision | 前后费率、影响汇总、样例及冲突明细、预览凭据和有效期；同一预览可分页读取明细 |
| POST `tenant.tenant/applySupplyMarkup` | tenant_id、preview_token | 已保存的费率、版本、生效时间和行摘要；恢复标准价复用此接口 |
| 现有租户列表 | 原分页和筛选参数 | 有权查看价格的管理员同时获得本页租户的费率摘要，一次关联查询或批量读取 |

预览沿用现有商城的 5 分钟有效期，绑定管理员、目标租户、费率、当前版本，以及实际影响结果的目录和价格指纹。确认时在事务内复核，统一平台规则、租户规则及新配置的加锁顺序。首次插入受唯一键保护。两个管理员同时编辑时，后提交的旧预览得到“价格已变化，请重新预览”。对同一成功请求重试返回原结果，避免二次记账式留痕。校验超范围、已删除租户、越权、过期预览、价格冲突时返回可操作的提示，整笔写入回滚。

为查看和调价设置独立权限点。按现有菜单权限机制同时保护前端入口与后端接口。租户只在自己的商城、明细及账单看到自己的实际进货价；客户目录只返回适用于该客户的售价。

开发第一步对服务端各调用点检索 `sale_points`、`platform_sale_points`、`platform_price`、`tenant_cost_points` 和直接构建价格快照的路径。逐项标记是平台标准报价、租户实际成本、客户售价，还是历史快照；对仍直接读标准价的租户成本调用补齐显式租户参数。平台的上游同步继续写标准数据，专属倍率按读时计算。

### 提交、结算与历史数据

- 接受新任务时，在服务端核对报价，记录租户 ID、规则版本、标准供货价、实际进货价、客户售价、SKU、分项费率和计费单位，并使用同一版本执行余额预检和预占。旧报价跨越调价时提示刷新报价，供货商调用以前完成校验。
- 成功后按任务快照中的费率与实际用量结算。失败、取消、部分成功和重复回调沿用该业务现有结算与退款规则，以原预占记录和快照为依据。对历史快照沿用其原有字段和费率，无需回填或重算。
- 仅在后台对账明细中补充本次供货规则来源。保留原语义所需的兼容字段，并通过版本区分新快照；避免无条件把旧字段改名而破坏尚在运行的任务。继续使用现有算力账户服务和流水，不直接更新余额。

## 五、验收矩阵

使用本地隔离租户 A、B、不同权限的平台管理员和可控上游回执。保存数据库记录、关键接口返回、浏览器观察及账单号作为验收依据。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 兼容与隔离 | 旧租户 A 无配置，B 设置 +20%，同一标准价 10 | A 进货 10，B 进货 12。标准目录仍为 10；交替读取两个租户多次无串价 |
| 零售策略 | B 分别继承、每单位加 2、加 25%、手动定价 16 | 客户单价依次为 12、14、15、16；应用独立免费时客户 0、租户 12 |
| 冲突与恢复 | 手动零售价 11，将成本从 10 调到 12；另测恢复标准价 | 首次显示对应规格并阻止保存；解决冲突后可保存；恢复后重新从标准价派生 |
| 分项与精度 | 输入、缓存输入、输出设置不同费率；图像含免费输入及付费超量；测试六位小数 | 每个收费分项只乘一次，免费项仍为零。人工按单位复算与后台金额一致 |
| 各终端及开放 API | 同租户同 SKU 在租户后台、PC、H5、小程序、开放目录查看并提交受控调用 | 各端按其角色展示的金额与预估、预占、实际流水一致；关闭的接口仍不可调用 |
| 余额边界与退款 | 调价后租户余额覆盖旧成本但低于新成本；另测用户余额不足、任务失败与重复回调 | 余额不足在上游执行前拒绝；退款按原冻结额，重复通知只产生一次有效结算 |
| 时间边界 | 预览后同步基价；任务提交后改价；回放旧格式账单 | 过时预览要求重算；在途任务用原快照，新任务使用新价，历史金额前后一致 |
| 安全与并发 | 无权限访问、跨租户/跨管理员复用预览、双开编辑、重复提交、保存中断 | 越权拒绝；过时编辑提示刷新；成功重试无重复变更，中断不产生半条记录 |
| 后台连续操作 | 第 2 页带筛选保存 B，再打开同页另一租户；模拟保存失败 | 成功只更新目标行，页码和滚动位置保留；再次打开显示对应租户，失败保留输入 |
| 目录规模 | 跨多页 SKU，冲突仅出现在最后一页；上游新增 SKU 后取价 | 影响汇总覆盖完整目录，分页结果可定位遗漏风险；新 SKU 自动使用当前租户费率 |

## 六、交付顺序与回退

1. **计价底座**　完成调用点清单、规则存储、幂等升级与全新安装 SQL、权限初始化、标量及分项报价。先用 0% 对照当前版本，比较目录、预占、账单与退款金额。
2. **消费链路**　接通终端目录、应用与开放 API、快照和对账，验证历史快照兼容。旧代码仍可能承担报价或结算的部署阶段，保持租户配置为默认值。
3. **平台操作**　实现租户行摘要、弹窗及预览确认，完成并发、冲突和第 2 页连续操作测试。后端 API、队列与结算进程全部更新后，再开放调价权限。
4. **上线验收**　先为一个受控租户启用，抽核一笔同步调用和一笔异步任务的报价、冻结与最终账单，再扩大使用。server 与 web 分仓交付，验收记录区分实际运行、模拟回执和待验证项。
5. **回退**　单租户通过「恢复平台标准价」停止对新单加价。系统回退先关闭调价入口，恢复受影响租户的新单标准价，保留新快照读取与结算能力直至在途任务结束。保留业务变更记录和已结算流水。
