# PC 生图上传与基础参数复核（2026-10-30）

## 用户可见问题和原因

1. FLUX 3 Klein 上传参考图后，估价报“参数格式不正确：image_urls[0]”，生成按钮不可用。上传组件保留 `url=blob:…` 供浏览器预览，同时将真正上传后的地址写在 `uri`；共享素材读取优先用了预览地址。使用相同冻结声明、相同业务参数和合成图片 URL 离线对照：只有 HTTP URL 时能构造，带 blob 预览和有效 uri 的浏览器形状请求会复现同一错误。此前只用 HTTP 参考图的目录探测没有覆盖该输入形状。
2. Qwen Image 2 的正式 `image_size` 枚举是宽高比，目录却同时把它投影成清晰度。PC 出现两个 1:1 控件，两个值可能覆盖同一个供应商字段。
3. 文生图、图生图 SKU 的同一比例被合并到一个列表，产生重复选项，当前模式的 SKU 选择还依赖报价时重新纠正。

## 共享修复

- `MarketImageReferenceUrlService::normalizeRequest` 同时处理 reference_images 和 typed reference_assets，选择真实上传 URI，经现有租户文件及 storage_scope/storage_engine/storage_domain 解析得到公开地址；保留角色、字段、附加参数和输入槽数量。不可提交的浏览器预览、本机 file 地址及未完成上传明确拒绝。原生模型、旧图片编码器及 Nano Banana 应用的准备入口共用此逻辑。图片模型的报价准入中直接调用 payload 的路径同样使用它。
- PC 的共用参数序列化将上传 URI 送入 url/uri，页面预览状态不改写；已有供应商资产 ID 保留。没有为 FLUX、Qwen 或业务工具添加型号分支。
- 按正式枚举区分比例型 image_size 与独立分辨率/渲染质量，保留 auto 的声明语义及不明确混合枚举的兼容行为。比例型字段不产生第二个清晰度控件；SKU 锁定比例仍保留。原生请求拒绝冲突或未声明的分辨率，避免覆盖实际比例。
- 共享图片通道为规格组补充兼容的 quality 别名，空规格组仍携带计价比例。共用表单筛选保留这一组，隐藏空清晰度控件。图片创作页和首页调用同一个比例/SKU 投影函数，按实际素材模式筛选并去重；完整 SKU 集合不删除，报价、SKU 锁定、结算和退款校验继续由后端负责。
