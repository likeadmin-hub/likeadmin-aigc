# 守护重启与系统升级

2026-11-03 现场只读检查：宝塔本站入口为 `start-ai-task-worker.sh`，状态为 STOPPED，未发现本站遗留 Worker。`site-update.lock` 的 READ 持有者为 php-fpm，随后 PID 改变。旧更新器将普通请求及长驻任务的读租约也当作升级前提，容易误报“仍有请求或更新正在执行”。

用户最终选择的流程是：**先升级成功，再按需提示手动重启或暂不重启**。不要求先停止守护进程，不自动调用宝塔重启，不新增长期运行快照或依赖仓库。

## 更新互斥

新更新器对 `site-update-intent.lock` 持有排他租约，阻止另一更新器并行写入，并暂停写入期间新进入的请求。对旧 `site-update.lock` 持有共享兼容租约：已运行的普通请求/Worker 可以继续；旧更新器的排他写入则仍会被挡住。子进程同时继承两把租约，父进程退出不能使新旧更新器交叉写入。不会删除仍被持有的锁文件，也不会终止已有请求或任务。

普通文件保留旧目标至原子 rename 发布新文件，临时回滚备份仍按现有事务保存和回收。长驻 PHP 进程已加载的类不会自动重载，后续加载的类仍来自普通站点目录，因此业务和数据库变更必须保持兼容。忽略重启只表示延后人工操作，不代表守护进程已加载新版本。

## 完成提醒

最终签名验证的更新内容决定 `restart_required`，与成功任务结果一起提交。页面/版本号更新不提醒；任务代码、依赖或迁移变化提醒。失败与结果未知不能进入成功提醒；SQL 不明状态仍禁止自动重放。

提示只在成功后出现，提供“已重启，关闭提示”和“暂不重启”。两者均关闭并刷新后台，不重新执行升级、不调用外部重启接口。自动升级与手动升级使用相同完成路径。确认仅是用户人工确认，不伪造现场验证结果。

## 宝塔守护配置

统一 Worker 首次收到 TERM 后通知并等待子进程收尾；等待阶段忽略重复 TERM/INT，全部结束后才清理当前 PID 文件。以下参数用于用户手动重启时可靠停止整组，不再是升级前的要求。完整示例为 `scripts/ai-task-worker.supervisor.ini.example`。

```ini
stopsignal=TERM
stopasgroup=true
killasgroup=true
stopwaitsecs=3600
```

## 验证

`direct-reader-drain.php` 覆盖旧读租约共存、新请求暂停、新旧更新器互斥；`direct-crash.php` 覆盖父进程死亡后两把租约仍由真实子进程持有；一次性 MySQL fixture 覆盖活着的伪 Worker 不阻断真实系统升级以及提交后的提醒字段。前端执行真实编译组件，覆盖成功提醒、纯静态不提醒、失败不提醒、自动更新及两个关闭按钮。
