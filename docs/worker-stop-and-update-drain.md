# 停止任务与升级排空

2026-11-03 现场：宝塔本站入口为 `start-ai-task-worker.sh`，状态为 STOPPED；`ps` 未发现本站遗留 Worker。`lslocks` 显示 `site-update.lock` 的 READ 持有者为 php-fpm，随后持有 PID 改变，说明普通 HTTP 请求仍持续进入。旧更新器使用一次非阻塞排他锁，普通轮询也会使升级立即失败，不能仅凭此错误判定任务进程未停止。

更新器现在先取得独立的站点更新准入锁，阻止新请求取得读租约，并等待已有请求最多 5 秒；排空后才替换文件。其他更新同时进入会被拒绝。超时保留原文件并自动释放准入锁，后续请求可恢复。仍保留任务进程检查、真实排他锁、继承子进程写租约及 SQL 不明状态禁止重放的约束；不删除锁文件、不绕过活动请求、不杀 PHP-FPM。

统一 Worker 入口收到首次 TERM 后通知并等待全部子进程；等待期间忽略重复 TERM/INT，防止父脚本先退出后遗留支付维护子进程。确认子进程全部结束后才移除属于当前脚本的 PID 文件。

## 宝塔守护配置

现有守护项的“配置文件”应包含以下参数，完整示例见 `scripts/ai-task-worker.supervisor.ini.example`：

```ini
stopsignal=TERM
stopasgroup=true
killasgroup=true
stopwaitsecs=3600
```

宝塔默认配置只有父进程停止和较短的等待时间；对于仍在执行的任务，超时 SIGKILL 父脚本会遗留子进程。进程组参数覆盖整组，等待时间允许当前受理操作完成。最终组级 KILL 仍可能打断真正超时的任务，因此先确认任务排空再升级；受理结果不明的历史任务只核对原任务，不重新提交。配置只针对本站守护项，不能停止其他站点的进程。

已有 1.0.429 站点尚未包含本修复。升级更新器前若撞到旧读锁，可待当前普通请求完成后重试，不能删除仍被持有的锁文件。源码修复需另行发布后才会影响客户站点。
