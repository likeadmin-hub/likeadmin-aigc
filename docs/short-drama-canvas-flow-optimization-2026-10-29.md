# 短剧与画布创作流程：问题、优化方案及验收步骤

日期：2026-10-29。范围：PC 短剧首页、故事/多集策划、剧本与分镜生产、短剧画布、独立画布、Agent 及共享模型计费。基线为本地 develop：server `7f5a21a27`、web `2cf51aa2`，已包含 `feature/short-drama-next-optimization`。

本次补充（方案评审）：针对“骨架缺少必要内容：subjects”和剧本生产反复失败，新增 [剧本生产可靠性专项方案](short-drama-script-reliability-plan-2026-10-29.md)。该方案详细规定每阶段返回契约、兼容白名单、角色/场景补缺、字段级修复、完整性清单、旧任务兼容、费用边界和待执行验收。用户要求先完善方案，本次没有继续修改业务源码或运行付费测试。下文第1节与第8节为上一轮已完成修改及验证记录。

本文把“本轮修复”和“后续方案”分开。源码审计和离线测试能够证明确定的程序缺陷，不能证明所有供应商在所有输入下都能成功。没有执行付费生成，也没有修改客户服务器或客户数据库。截图对应的具体任务、上游回包没有在本地找到；已复现同类数组转换错误，不能把它当作截图唯一根因。

## 1. 上一轮已完成的修改

### 1.1 恢复前端模型选择

- 短剧首页恢复模型入口，文本、图片、视频可以由用户选择；单集、多集和导入请求均传递选择。
- 故事策划页恢复选择入口，从任务返回的安全 `model_selections` 恢复原选择。
- 后端不再把用户显式选择的文本模型强制替换成租户默认。仅在没有选择时使用有效默认或目录候选。
- 短剧画布恢复文本模型设置，保留图片、视频设置；独立画布及短剧画布菜单采用官方优先的稳定排序。
- 模型目录投影统一官方/三方来源，复用已有标识组件；从渠道配置判断来源，不从模型名字猜官方。
- 有效选择仍要通过租户上架、SKU、所属媒体类型和可用性验证；无效显式选择明确报错，不静默换成别的收费模型。
- 已提交的任务、生成回执及冻结节点保留原模型身份。目录排序变化不能改变旧任务的查询或重放；下架模型不能用于新提交。
- 按真实视口限制长模型菜单高度；首页模型偏好空间不足时向上展开，底部悬浮输入框的菜单向上展开，选项可滚动。

本轮没有新增“租户承担文本费/Agent费”的配置，没有更改价格、余额与旧账。选择模型与费用承担是两件独立的事。

### 1.2 修复一条会绕过局部修复的剧本异常链

触发过程：关闭可选剧情复核 → 模型把 `story_outline` 等应该为字符串的字段返回成数组 → 旧代码直接 `(string)` 转换 → PHP 抛出 `Array to string conversion` → 异常类型不是已有修复流程识别的 `RuntimeException(422)` → 已收到的坏回包再次被重放，用户继续后仍可能卡住。

修复：无论是否开启可选剧情复核，基础结构校验始终生效。错误指出具体字段，进入原有局部修复。素材 ID/名称/描述、连续性规则出现结构值时，明确要求修正，不写成 `Array`、不擅自展平、也不把已确认事实悄悄丢掉。

测试已经覆盖历史 `received` 坏回包：前 10 集合格内容保留，只为第 11 集新建一次修复调用；历史回包原文不变。这里是隔离的内存测试，未实际请求供应商或扣费。

## 3. 建议的用户创作主流程

### 第 1 步：创意、素材和生产设置

用户填写创意，选择单集/多集、时长/画幅，上传或绑定参考素材。一个清晰的“模型与费用”入口包含文本/图片/视频，官方排前、三方明确标识，同时显示模型能力和当前阶段价格方式。

前端只提交用户意图和模型 ID；服务器验证归属、上架、能力、输入结构和承担策略。纯编辑、保存、选择素材不产生模型费用。输入自动保存，切换页面恢复草稿。

### 第 2 步：故事设定

服务器先核对本阶段输入与模型容量，确定实际模型，再创建有预算和策略快照的任务。后台完成模型调用、回包保存、结构校验和有限局部修复。前端显示真实排队/生成/修复状态、已用时、已有内容，不能伪造百分比。

用户只确认人物、世界观、风格等关键内容。语法修复、JSON 规整、轮询、工作记忆整理不要求用户逐步点确认。

### 第 3 步：全剧规划和分集大纲

多集任务先建立全剧节奏和连续性事实，再按模型容量分批生成大纲。内部批次可以变小，已通过的集不能被整体重写。用户看到“已完成 N/M 集”和可预览的大纲，不直接面对规划单元或技术重试。

大纲确认时一次选择生产范围、连续生产/分批检查、文本预算。更改故事事实产生新版本，只重算受影响阶段；旧版内容保留并标为需复查。

### 第 4 步：剧本、分场和分镜

每集独立持久化检查点，按场景和镜头分段生成。始终执行结构校验；剧情与连续性质量复核是另一层，可选。局部缺字段或坏格式只修该字段/镜头/集，不整剧重做。

正文与复核状态分开：正文完成即可查看；待复核明确显示，后集不能把未核实事实当成已确认状态。预算不足暂停剩余步骤，已完成正文可用。

### 第 5 步：角色、场景和分镜图片

先检查已有素材是否可复用，列出复用数量和本次 0 点。对于新增素材，显示数量、规格、模型渠道、单价/用量方式及本批应付；用户确认后进入后台批量任务。

角色、三视图、场景有归属和生成签名校验，跨集优先复用。不要因打开页面或整理画布重新生成。局部失败只补失败项；节点变动先标记需复查，不自动收费重做。

### 第 6 步：镜头视频和声音

用户选定图片、动作、时长，确认本批视频及配音/BGM费用。提交前重新验证规格和价格；发生实质费用变化时重新确认。媒体并发由供应商限制和任务预算控制。

读超时、断线、不确定是否受理：查询原任务和消费记录，不能直接二次提交。仅明确未提交或原费用已核对时才提供安全重试。输出先转存并核对可访问性，再标记可用于合成。

### 第 7 步：时间线、合成和导出

时间线编辑、镜头替换引用不额外调用模型；选择旧素材时显示其版本。当前本地 FFmpeg 合成与 ZIP 导出为 0 点，应明确标为免费，不显示虚构模型价格。

合成失败保留已生成媒体，只重新执行本地合成，不再次生成图/视频。最后由用户检查画面、字幕、声音与连续性；“任务成功”不能代替成片质量验收。

### 第 8 步：完整费用与恢复

项目内一直可查看本次累计支出、预占、已退回和待核对金额。详情按故事/大纲/剧本/理解/修复/Agent/图片/视频/声音归类，可复制平台与上游任务 ID。技术 ID 放在详情内，不占用创作主区域。

刷新、断网或重新登录，读取原任务和检查点继续显示，不重新发起收费生成。

## 4. 画布与 Agent 应如何简化

用户主视图保留需求输入、模型选择、画布结果、当前阶段和费用。每个节点都有 source/version/task/consumption 引用，但仅在详情展开。

Agent 内部执行：理解需求 → 读取必要上下文 → 形成有界方案 → 工具预检与估价 → 已授权范围内执行 → 回收结果。一次用户请求中的话题分类、长文分块、格式修复都属于同一父 run，费用可以合并展示，后台仍逐次留账。

- 可以自动：参数规整、必要上下文提取、结构修复、回执查询、存储重试、轮询、已有素材复用、预算内继续执行。
- 应保留决策：事实冲突、用户意图不明、选择不同收费模型、改变规格/数量、新媒体批次、超预算、结果不确定且可能再次收费。
- 自动模式必须有 project/run/stage 金额与调用上限。当前 Agent 单 provider 最多 8 次，只是循环保护，不能代替整次请求的金额预算；长资料最多 8 文件、每文件最多 128 批，也不适合当用户预算。
- 不为解释费用再调用模型：由账本直接汇总。内部提示词优化先复用已有版本；能确定的媒体可用性检查提前完成。
- 保留原有工具去重、提交锁、价格变化重确认、历史会话只恢复消息、不自动恢复历史收费动作的保护。

## 5. 每一步的承担方和费用方案

### 当前真实行为

普通用户文本/Agent：用户付租户零售价，租户付平台成本价，两套金额独立。配置“默认文本模型”不会改变承担方。租户后台 `userId=0` 的专用调用可以把用户价格设为 0，但不能给普通用户冒用后台身份。

### 建议后台配置（尚未实现）

短剧、画布分别增加：`创作文本费用承担方=用户/租户`、`Agent文本费用承担方=继承创作文本/用户/租户`、`内部辅助费用承担方=租户/继承`。建议内部修复、路由和提示词整理默认租户承担；用户主动重写、文本创作和媒体是否补贴由租户选择。

同时配置单任务 token、金额、调用次数与修复上限。费用承担策略、价格和版本由服务器解析并在提交时冻结，不能信任前端传 `payer`，不能为了补贴把共享 SKU 售价全局改成 0。已有任务延迟结算、退款与恢复沿用原快照，新任务才使用新配置。

“租户承担”表示用户本次应付 0、无用户扣款，租户仍支付真实平台成本；不是给租户叠加扣一次用户零售价。Agent 文本补贴也不代表图片/视频自动免费。

| 步骤 | 当前是否可能收费 | 目标展示和承担规则 |
| --- | --- | --- |
| 编辑/自动保存/上传登记/选择素材 | 无模型费用；存储政策另议 | 明示无需生成费用，不额外弹报价 |
| 故事/大纲/剧本/分镜文本 | 按真实 token 结算，每次调用独立记录 | 使用创作文本策略，显示承担方、累计已扣和预算 |
| 视觉理解/参考图描述 | 独立文本调用 | 纳入文本策略，不藏在免费编辑后面 |
| 内部格式修复/提示词整理/路由 | 可能另有文本调用 | 建议租户承担；向用户收费时必须包含在事前预算和事后分项 |
| Agent 规划/工具循环/资料读取 | 多次文本调用，媒体另计 | 使用 Agent 文本策略；同一 run 汇总，设总上限 |
| 角色/场景/三视图/分镜图片 | 固定计价可预占；实际用量 SKU 等 usage | 列数量/规格/渠道/应付，不能把未知用量写成固定总价 |
| 视频/配音/BGM/转写 | 独立媒体任务 | 逐批报价、预占或真实用量结算；不继承“文本免费”的误解 |
| 已有素材复用/同回执重放 | 不再调用供应商 | 显示本次 0 点，保留原素材及原账单引用 |
| 本地合成/ZIP导出 | 当前 0 点 | 显示免费；失败只重试合成，不重生成媒体 |
| 已受理但结果/用量不明 | 不能直接视为免费或全额退款 | 显示待核对，查询原任务；核对后按真实状态结算/释放 |

统一费用卡应包含：本阶段用户预计应付、租户承担提示、预占、已扣、退回、待用量/待核对；技术明细在展开层。金额来自消费账与两侧资金流水，不能把父任务状态当作整个项目的收费状态。

详细代码证据、8项计费缺口和对账步骤见 [计费专项审计](short-drama-canvas-billing-audit-2026-10-29.md)。

## 6. 分阶段实施顺序

### 阶段 A：恢复可操作性与确定异常（本轮）

1. 恢复三类模型选择、官方优先及实际请求参数。
2. 后端验证显式选择，任务返回安全选择快照；旧收费任务不换模型。
3. 修复数组类型异常和连续性事实静默丢失。
4. 定向离线回归、隔离构建、真实页面可见性检查。

### 阶段 B：让长剧本稳定推进（后续）
