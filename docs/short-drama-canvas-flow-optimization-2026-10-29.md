# 短剧与画布创作优化方案（按现有业务兼容修订）

日期：2026-10-29。状态：方案评审，尚未实施本次修订。最新用户约束优先：**取消所有人为累计预算与次数封顶，费用由用户承担，保留现有创作流程和生成方法，只做兼容性与可靠性优化。**

上一版关于设置任务预算、租户承担辅助费用、新增连续生成选择、删除或调整确认流程的建议全部撤回。本次同步修订总体方案、[剧本专项方案](short-drama-script-reliability-plan-2026-10-29.md)和[费用专项审计](short-drama-canvas-billing-audit-2026-10-29.md)，仅修改文档，没有修改业务源码、测试、数据库或运行配置，没有调用付费模型。

范围：现有单集、多集、导入、局部修改、短剧画布、独立画布、Agent及关联图片/视频/文本业务。源码审计与实际供应商验收分开；截图任务的原回包尚未取得，不把静态推导当现场唯一根因。

新增客户反馈已纳入两个 P0：[API 定价死锁与短剧生图参数专项](market-pricing-and-drama-image-feedback-plan-2026-10-29.md)。分别补充逐商品配置保存的并发/事务/提示一致性，以及已有剧本生成主体场景图时的 prompt 契约、模型协议、逐项受理和费用恢复。本次仍只完善方案。

## 1. 上一轮已完成的修改

### 1.1 恢复前端模型选择

- 短剧首页恢复模型入口，文本、图片、视频可以由用户选择；单集、多集和导入请求均传递选择。
- 故事策划页恢复选择入口，从任务返回的安全 `model_selections` 恢复原选择。
- 后端不再把用户显式选择的文本模型强制替换成租户默认。仅在没有选择时使用有效默认或目录候选。
- 短剧画布恢复文本模型设置，保留图片、视频设置；独立画布及短剧画布菜单采用官方优先的稳定排序。
- 模型目录投影统一官方/三方来源，复用已有标识组件；从渠道配置判断来源，不从模型名字猜官方。
- 有效选择仍要通过租户上架、SKU、所属媒体类型和可用性验证；无效显式选择明确报错，不静默换成别的收费模型。
- 已提交的任务、生成回执及冻结节点保留原模型身份。目录排序变化不能改变旧任务的查询或重放；下架模型不能用于新提交。
- 按真实视口限制长模型菜单高度；首页模型偏好空间不足时向上展开，底部悬浮输入框的菜单向上展开，选项可滚动。

本轮没有新增“租户承担文本费/Agent费”的配置，没有更改价格、余额与旧账。选择模型与费用承担是两件独立的事。

### 1.2 修复一条会绕过局部修复的剧本异常链

触发过程：关闭可选剧情复核 → 模型把 `story_outline` 等应该为字符串的字段返回成数组 → 旧代码直接 `(string)` 转换 → PHP 抛出 `Array to string conversion` → 异常类型不是已有修复流程识别的 `RuntimeException(422)` → 已收到的坏回包再次被重放，用户继续后仍可能卡住。

修复：无论是否开启可选剧情复核，基础结构校验始终生效。错误指出具体字段，进入原有局部修复。素材 ID/名称/描述、连续性规则出现结构值时，明确要求修正，不写成 `Array`、不擅自展平、也不把已确认事实悄悄丢掉。

测试已经覆盖历史 `received` 坏回包：前 10 集合格内容保留，只为第 11 集新建一次修复调用；历史回包原文不变。这里是隔离的内存测试，未实际请求供应商或扣费。

## 2. 本次方案的固定边界

| 用户要求 | 实施约束 |
| --- | --- |
| 不因内部预算停止 | 取消项目/任务/阶段/Agent累计金额、点数、Token、总调用、修复次数及累计创作耗时封顶；旧任务也不因同类累计计数停止 |
| 用户承担费用 | 所有实际文本、Agent、理解、辅助修复和媒体调用按现有用户价格结算；不新增租户补贴或承担方配置 |
| 不改创作流程 | 保持入口、页面、步骤顺序、手动/自动、已有确认、导入、修改、模板、时长和生成方法 |
| 不影响既有业务 | 原先正常输入、已支持返回格式、模型参数、素材绑定、报价、扣费、退款、结果与历史任务都纳入兼容回归 |
| 图/视频/文本都能衔接 | 修复内部解析、字段传递、引用、任务状态、存储、调度及计费关联，不能只修文本页面 |
| 真实异常如实处理 | 保留实际余额、模型物理能力、供应商限流/拒绝、权限、数据归属及不确定受理核对，不把这些误称为内部预算 |

“所有条件”的工程验收口径是覆盖全部现有业务分支、合法输入形态及可恢复异常；有效输入和可用上游条件下，不能因内部逻辑缺陷导致失败。外部供应商停服、拒绝、实际资金不足或客观规格不支持时，系统应给出真实状态、保存结果并沿现有路线恢复，不能假成功。

## 3. 已发现的问题与调整方式

| 问题 | 导致的情况 | 保持原方法的优化 |
| --- | --- | --- |
| 新旧入口封装、字段别名和JSON解析不同 | 同一回包在不同入口报缺字段或丢内容 | 对齐已支持格式；协议适配、类型检查、阶段校验一致，不能提高业务门槛 |
| 骨架缺subjects/locations时局部修复不能接手 | 整份骨架重复生成，已有场次可能漂移 | 先核对明确别名/封装和权威素材，再仅补缺失字段；场次与ID冻结 |
| 非空校验后直接做字符串/数组运算 | 数组转换、TypeError、坏引用进入后续步骤 | 在原函数边界补类型与引用检查，异常进入既有恢复路线 |
| 累计调用/输出/复核/重试封顶 | 剧本未完成却因内部计数失败 | 清除累计停止线；保存进度，在同一任务中继续，不能靠把上限调大交付 |
| 单轮dispatch边界与业务终态混淆 | 等待下一轮被显示为失败，或需反复手点继续 | 时间片仅用于调度，自动续处理；原有人工确认节点不变 |
| 模型容量元数据缺失或保守估计被误当真实能力 | 合法长剧本被提前挡住 | 核对所选渠道能力，沿现有分段/续写方法处理；不擅自换模型、不截掉明确事实 |
| 辅助文本费用及已发生支出展示不完整 | 用户看到的报价与累计费用不清楚 | 在原费用区域补分项、实际支出与状态，不新增报价步骤 |
| 图/视频引用或状态恢复与正文版本不一致 | 文本成功但素材生成失败，刷新后重复提交 | 同一项目/版本/任务关联；核验真实参数、归属、结果转存与幂等 |
| worker未完整启动或未加载新版本 | 后台待处理不推进 | 核对规划/剧集/画布消费者和版本；不能把部署缺项归因于用户预算 |
| 租户 API 定价按商品并发保存，多处竞争规则锁 | 多条1213死锁；部分商品提交；成功失败提示堆叠 | 保留原页面/逐商品接口，顺序提交、防重入、统一结果；后端统一共享锁序与本地事务恢复，保留售价规则 |
| 策划页与工作台提示词字段不同，模型协议校验需贯通 | 正文已存在却报必填prompt，媒体环节无法推进 | 对齐原字段及权威资料、报价/预占/提交的最终内容与Schema；后端已有提示词构建，不能仅补前端字段就认定根因已修复 |
| 策划页主体场景图仍并发提交，首项失败提前清状态 | 剩余请求继续受理；重试/旧失败任务判断可能阻断或重复提交 | 复用既有工作台逐项提交/回查，区分已受理、明确失败与未知结果，成功素材保留，缺项沿原方法恢复 |

本地此前只读进程检查发现短剧画布Agent worker存在，规划/剧集worker未见；客户服务器未核验。本次不启动消费者，以免处理现存任务产生模型费用。

## 4. 预算封顶清除与调度的具体范围

1. 去除按累计金额、Token、预留输出总量或调用数量决定失败/暂停的逻辑。
2. 去除格式修复、复核、生成单元和Agent固定总次数耗尽后要求缩小范围/新建任务的分支。
3. 检查历史预算字段、默认值、前端状态映射、错误提示及恢复键序列，避免仅删一个判断仍留下其他停止线。
4. 单轮dispatch、分页、分块和worker时间片可以保持，但结束后必须自动继续同一任务；不作为任务预算。
5. 重复回执与重复工具提交继续幂等；识别相同缺陷后携带准确目标修复，不盲目重放同一付费请求。
6. 取消累计预算不取消单次模型实际上下文/输出参数。继续用现有分段方法，按真实能力续处理，保持原剧情和时长。
7. 实际余额不足、上游拒绝、结果受理不明、用户取消沿现有业务处理，不伪装为内部封顶。

具体位置与验收见[专项方案的限制清单](short-drama-script-reliability-plan-2026-10-29.md)。取消消费预算不能顺带改写原有镜头时长分配，也不能删除真实供应商规格检查。

公共图片运行时的固定提交次数和数据库提交通道等待片也纳入核对：单次时间片可以结束，但可恢复任务应在原任务续处理；明确未受理与受理不明分别处理，不能取消预算后盲目重发。定价配置死锁仅允许完整回滚后的本地事务恢复，不可重放整个收费请求。

## 5. 按原有创作顺序优化，每一步如何处理

以下对应已有业务路径，不要求所有入口新增相同步骤；单集、多集、导入、修改继续各走其现有方法。

| 现有环节 | 仅做的优化 | 费用规则 |
| --- | --- | --- |
| 输入、上传、选择模型/素材、保存 | 参数和归属校验、草稿恢复；保留现有界面与选择方式 | 原本免费动作保持免费 |
| 故事设定/全剧规划/分集大纲 | 兼容格式、检查类型与连续范围、补缺失集，已通过内容保留 | 实际文本调用由用户按原价格承担 |
| 单集骨架/分场/分镜 | 角色场景权威继承、字段补丁、原方法分段续写；不更换模板或创作方法 | 实际新增调用由用户承担，本地解析/继承不新扣费 |
| 可选复核/局部修改 | 保持原启用条件与修改范围，修复字段不重写合格正文 | 用户承担真实调用费用；无累计复核停止线 |
| 画布/Agent对话与工具执行 | 适配输出、参数衔接、检查点、去重、真实进度 | 按原手动/自动授权执行；用户承担实际文本和工具费用 |
| 角色/场景/分镜图 | 保留原主体/场景/参考图和规格策略，修复参数传递及状态回收 | 沿原报价、预占/用量结算，用户承担 |
| 镜头视频/声音 | 保留原首尾帧、多参考、时长、配音/BGM方法，修复引用、存储与恢复 | 沿原媒体收费标准；受理不明先查询原任务 |
| 素材复用/本地合成/ZIP导出 | 保持原复用和导出方法；失败只恢复相应环节 | 复用不再次生成；原本0点的合成/导出保持0点 |
| 查询历史/刷新/断点恢复 | 读取原任务、回执与当前版本，不重新生成已完成内容 | 查询、重放本地回执不新扣费 |

费用卡在原区域补齐用户预计应付、已扣、预占、退款、待用量/待核对及分项明细。预估用于说明，不是任务停止预算。租户成本账、价格快照和PointService继续保留，不新增补贴配置，不改变原价格、退款和结算方法。

## 6. 工程实施顺序

1. **先建兼容基线**：盘点单集、多集、导入、修改、画布、Agent和媒体的原有入口、模板、步骤、确认、参数与成功样本。
2. **定位并清除所有累计封顶**：金额、Token、调用、复核、修复、历史预算及状态映射逐项登记；调度自动续处理，保留原请求与价格身份。
3. **修复解析和字段传递**：统一已支持格式的无损适配、类型检查、角色场景补缺及现有局部修复。
4. **修复原任务恢复**：坏回包保留、已通过单元复用、缺项继续、worker状态和租约核验；不新增创作步骤。
5. **核对图/视频/文本衔接和费用**：同版本素材、真实模型参数、受理结果、存储与消费记录贯通，保证不重复收费。
6. **执行兼容验收**：原正常业务零回归；异常覆盖、跨原封顶继续、多集到媒体生产及账单核验分别出报告。
7. **按原发布流程交付**：开关/版本兼容与回滚准备，核对worker加载；本次只完善方案，不发布。

新增 P0 与上述步骤并行纳入：在兼容基线后先收敛配置保存的并发/锁序和结果真实性；步骤3同时打通策划页到图片报价/预占/提交的参数契约；步骤4复用原逐项受理回查；步骤6加入音乐多API保存与截图Qwen Image 2.1生成主体场景图的回归。具体源码证据、排查树和验收顺序见[新增反馈专项](market-pricing-and-drama-image-feedback-plan-2026-10-29.md)。

不新增预算配置、承担方切换、连续创作模式或确认页，不替换现有Agent、剧本规划或媒体生成方法。

| 场景 | 必须满足 |

| 文本到图/视频、首尾帧与参考素材 | 原参数策略不变，ID/版本/归属正确，不因内部衔接失败 |
| 用户承担与真实余额不足 | 沿原价格结算，资金异常如实显示；不新增租户承担或内部预算停止 |
| 刷新、断线、并发、重复回调 | 原任务继续核对，去重、不重复生成或结算 |
| 上游限流/拒绝/停服/不确定受理 | 真实状态与原恢复能力可用，不假成功、不盲目重复收费 |
| 本地导出失败 | 已生成媒体保留，只恢复导出，原免费项目不新增收费 |
| 多API定价、改成本/规则/能力/同步竞争 | 原页面保存准确，单商品事务完整；部分提交如实报告；不覆盖新价格或历史消费，不出现同页重复提示/重叠写入 |
| 策划页生成主体场景图、平面/结构化协议 | 原角色场景与模板不变；最终prompt与Schema/模型协议一致；报价、预占、提交参数贯通，无新增prompt表单或付费补词步骤 |
| 主体场景图批次部分受理/失败/未知/历史失败 | 已受理和成功素材保留；明确缺项可恢复；未知先回查，不重复生成或收费 |
