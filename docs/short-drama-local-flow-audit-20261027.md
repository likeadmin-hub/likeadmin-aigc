# 短剧生成本地流程核查（2026-10-27）

## 核查边界

只核查本地提交、接收、解析、规范化、校验、持久化和恢复。正确返回被本地拒绝、丢失内容、向下一步提交互相矛盾的要求均属于本地缺陷。上游自身缺失内容、错误剧情、截断或拒绝不通过放宽验收来掩盖。

本次覆盖常规单集、多集设定与大纲、逐集正文及其共用服务；画布复用的生成、时长和接收逻辑通过共用回归检查。不是图片、视频、音频生产全链路审计，也不包含新一轮付费模型质量评测。

## 六处修复及其边界

1. **时间码部分结果被当成整集。** 两段各 5 秒的有效返回，生成第一段后会因“只有 5 秒而非整集 10 秒”终止，第二段根本未请求。时间码标记函数现在只负责标记；完整生成后仍严格验证整集时长和逐段边界。
2. **相邻空间被误判。** “陈溪站在办公室门外”正确绑定走廊时，本地正则曾强行推断为办公室。新契约不从相对方位或否定移动中推断实际场景，仍接受明确登记的更长场名，仍阻止明确的场内冲突与室内外冲突。
3. **大纲尾批 1 集漏投影。** 内部尾批、单集修订和拆批中的 1 集曾被误判为非多集规划，重复携带完整结果及制作字段。新契约依据内部批次标记、阶段和全剧总集数识别，保留故事事实和原始要求，并去掉非创作运行字段；普通单集正文不进入多集流程。
4. **保存后改变时长规则。** 新生成以默认时长为参考，140 秒合法结果在保存后复核却被按 130 秒硬上限拒绝。结果设置现在记录生成契约版本，时长复核读取同一版本；用户明确指定的时长仍严格匹配，缺少版本的历史结果保持旧语义。
5. **本集要求被本地剪裁污染。** 原文“第2集：追到车站。母亲上车。”曾只删掉第一句而留下“母亲上车”，使后续要求提取失去所属集信息。新契约不再做这种有损删除，完整保留原文；较长原文优先按句/行分块并携带前一范围标题。模型仍负责判断原文的创作含义，本地不再自行改变其范围。这会在开启内容复核时多保留一些输入，优先保证语义正确。
6. **流式换行跨包丢失。** 先对每个网络块替换 CRLF，遇到 CR 与 LF 分处两个块时会丢失事件分隔符，并把多个正确事件合并成无效 JSON。接收器改为缓冲后处理，保留待判定的末尾 CR；支持 LF、CRLF、CR、单字节分包、中文跨字节、usage 尾包及原生结束事件。没有修改计价或用量换算。

## 版本与恢复

- 新请求使用输入契约 v17；改变模型上下文的规则按版本启用，v16 及更早任务保留原有请求投影和范围处理，避免付费收据的输入签名被静默改写。
- 中间进度保存和流式接收是本地缺陷修复，可以应用于原有执行流程；它们不改已冻结的模型请求。
- 新规范化的结果记录 `generation_settings.input_contract_version` 与 `timing_recovery_enabled`，后者保留旧任务显式继续时的时长恢复策略。无数据库迁移和 API 路径变更。
- 不把历史失败任务改为成功，也不自动重新扣点。旧任务如果受旧上下文规则影响，需要单独选择恢复/新建策略，不能声称所有历史失败已被修好。

## 再次核查：从词语补丁改为结构校验（v18）

### 新证据

只读核对最近七天的失败记录后，发现 v17 任务 `sd_plan_202610271631587757` 的三次骨架返回都登记了 `loc_office / 人间办公室`，正文写“深夜办公室，林小凡独自加班”。规范化已接受该简称，随后 `assertBeat` 却再次按精确名称查找“办公室”而失败。离线原样复现成立，不是上游缺少场景。统一简称解析后，三份收据各 13 场的完整骨架均通过校验。

另一个可复现缺陷是 PHP 将场景索引中的数字字符串键转为整数，导致声明为 `"101"` 的 ID 被规范化成 `101`，随后严格引用比较失败。索引现在保留声明 ID 的原始值和类型；字符串、数字字符串、整数 ID 都有完整生成路径回归。

旧 v13 失败记录的第 8 场明确要求 `loc_lingxiao`，返回却使用 `loc_renshisi`，属于提交约束与上游字段不一致，未通过放松引用校验来掩盖。

### 用户要求后的机制调整

单纯继续补地点词、否定词和方位词，不能穷尽自然语言。新任务改用输入契约 v18，将可确定的结构校验与语义判断分开：

1. **场景绑定以显式字段为准。** 校验场景 ID 是否登记、显式场景名称/别名是否属于该 ID、已声明的室内外是否一致。正文、动作、开场和收场不再经过地点词推断，也不再据此改绑或判失败。同名地点由 ID 区分。
2. **运镜正文不是切镜协议。** 不再把时间段数量直接当成切镜数量，不再把姓名子串当成可见角色证据。模型能力和连续镜头要求仍保留在提交说明中；主体 ID、镜头时长等结构检查保留。
3. **后处理保留明确结果。** 不再根据“办公室”等词覆盖室内外字段，不再按情绪关键词把台词括号内容搬到画面描述；新契约不进入旧版逗号姓名归属恢复。缺少室内外时只能继承明确登记的场景字段，不能从正文猜测。
4. **语义候选不能直接变成错误。** 第三人称句式由现有内容审校判断；相邻重复台词也须经过已有重复语义核实，不能因缺少某个“允许重复”关键词就直接进入修复。合理呼应可保留，经核实的无理由重复仍进入原有修复流程。
5. **复核沿用生成时长原则。** 不再在补丁阶段用字母/字符数估算拒绝已接受或未改动的台词。补丁仍禁止修改时长、镜头数量、未知引用及非目标字段；明确时长和时间码仍由原有结构规则严格检查。

这没有把模型语义审校替换为“全部通过”，也没有开启额外的强制审校。语义复核仍遵循任务原有质量检查设置，模型仍可能误解剧情。没有实际语音测时，因此不声称验证了每句对白的真实朗读时长。JSON、不完整回包、非法引用、明确字段矛盾、锁定时间不符等失败处理保留。
