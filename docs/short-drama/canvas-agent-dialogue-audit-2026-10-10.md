# 短剧画布 Agent 全链路审查与调整

日期：2026-10-10。范围：整个短剧画布 Agent 的对话、任务状态、上下文、解析、执行、媒体与界面协议；并非针对某条消息的特例。

## 目标与既有产品约束

每轮先理解用户当下的意图，再选择聊天、澄清、信息更新或执行。历史任务持续保留，但不强制占用下一轮对话。用户可以在同一会话讨论、提供参数、纠正、暂停、恢复。

保留已经约定的制作顺序：确认剧本 → 主体和场景 → 三视图就绪 → 分镜 → 确认后插入分镜视频节点，由用户在画布自行生成。保留普通短剧创作共用的正式任务、提示词和素材引用链路。不新增本地内容质量评分或镜头时长分配。

## 已核对的结构与问题

| 环节 | 现状/证据 | 本轮调整或明确边界 |
|---|---|---|
| 入口 | ConversationService 区分自动阶段协议与普通文本，但 reviewing_intake 被一律冻结 | 未执行的采集卡允许本轮语义提取；对话更新缺项，不绕过媒体确认 |
| 意图 | WorkflowTurn 已有 speech_act / deliverable / scope；暂停和恢复没有独立状态 | 加入明确的 pause/resume 决策；低置信、询问操作方法不能执行 |
| 普通交流 | Worker 对固定问候词仅传一条消息，丢弃上下文 | 移除问候绕过通道，使用统一对话原则和带来源的上下文 |
| 回复 | 待确认分支强制覆盖模型的自然澄清 | 保留非空自然回答；无有效回答才使用简短兜底；节点操作仍独立验证 |
| 信息来源 | CreativePlan 区分 message/confirmed/delegated/suggestion，但提示词会过度禁止讨论建议 | 明确允许咨询和建议，禁止把建议直接变成制作参数 |
| 记忆 | 入队快照最近38条，活动工作流又压到6条每条600字 | 活动对话保留最近12条、每条2000字，标识截断；单独提供阶段状态、暂停、已确认槽位、待定建议和保存成果 |
| 上下文边界 | 旧产物和技能说明可能压过本轮问题 | 普通意图路由不叠加阶段生成提示词及镜头时长说明；本轮请求优先，材料不具有执行权限 |
| 长期记忆 | 结构化槽位、版本化成果持久化；任意闲聊超过窗口并无无限记忆 | 不承诺记住未提供的早期闲聊；重要制作事实从结构化状态与成果恢复。全历史语义检索、自动摘要不是本轮伪造出来的能力 |
| 执行 | 页面就绪阶段会自动续跑，缺少用户暂停状态 | 持久化 execution_paused；前端自动执行/自动确认与后端自动阶段入口均检查。恢复不绕过原有确认 |
| 进度 | 前端曾把会话阶段误当本轮阶段，随后用固定提示词匹配 | run.activity 来自后端冻结上下文；未知/分类中按普通回复展示，不猜阶段 |
| 模型选择 | 活动工作流强制覆盖本轮聊天模型 | 尊重本轮对话模型选择，仍通过租户模型目录授权；正式生产模型与生成模式继续使用已确认快照 |
| 工具 | 白名单技能、结构化节点提案、人工确认、正式生产任务 | 保留有界执行。技能推荐不是执行成功，聊天文本不能直接收费或写节点 |
| 多模态 | ConversationImages / Attachments 和市场 provider 做来源、可见性及模型能力筛选 | 本轮不改资产访问控制；不能从图片标题/文件名声称看过像素，音视频未解析不能声称理解 |
| 重试与费用 | Provider 明确拒绝可换模型；未知结果走 reconciliation；run request_key 幂等 | 保留，不因聊天优化扩大重试或重复付费。上游成功但本地结果不明仍需恢复机制处理，不能假报失败退款或自动重跑 |
| 事件与历史 | messages/events/SSE 分离，终态排空消息，卡片绑定原始 run | 保留时间顺序和来源定位；不覆盖历史、不把原卡复制到最新消息 |
| 运行隔离 | tenant/user/canvas/thread 四维访问控制、版本CAS及队列租约 | 保留；普通聊天不能跨项目改状态，暂停只作用于当前会话 |

## 可验证的行为基线

- “你好”“先聊聊”“你能做什么”：自然回应，无阶段推进或催填信息卡。
- 重复作品名：结合最近上下文承接/澄清，不推定为确认或自动开始。
- “一集60秒”：更新用户明确提供的参数，只留下缺失的风格/比例。
- “你觉得竖屏好吗”：回答建议，不标记用户已选择竖屏。
- “改成横屏”：采集阶段记录明确纠正；已生产内容仍遵循版本/确认边界。
- “暂停制作”：保留槽位、成果与画布，停止后续自动阶段；不声称取消已提交任务。
- “恢复制作”：恢复后续执行资格；缺项/待确认/素材依赖继续生效。
- “先别生成，解释一下这个镜头”：只解释；不能把解释请求当作重做。
- 独立写文案、解释概念：在已有项目时仍可回答，不强制切换/覆盖项目。
- 网络断连和页面刷新：读取服务端权威状态，不根据文本或前端默认值推测已经生成。

## 验证方法与限制

单元/契约测试验证解析、状态边界、上下文限额、进度来源、媒体依赖与历史恢复；事务回滚测试验证信息采集与确认写入。使用假 provider 的事务回放验证 Worker 到持久化的完整链路，不产生模型费用。

这些测试验证控制逻辑，不证明任意模型对任意自然语言都能正确分类。真实模型的多轮评测需要另行授权调用成本。上线前应按上述语料增加中英文、同义句、否定、指代、混合请求和长对话回归；观察错误类型而不是只检查“接口成功”。

## 本轮验证记录

第一轮后端95项测试/562个断言、前端46项测试通过。聊天、暂停、恢复、补充采集四种 Worker 事务回放成功，并核对回滚后原会话未变；未调用真实模型。后续对话模型选择与自然澄清补充测试另行复跑。
