# 模型调用与任务结果收口实施方案

分支：`feature/short-drama-next-optimization`，server／web 两仓分别提交。沿用现有授权：不创建或查询真实供应商生成任务、不收费生成、不修改真实任务／售价／上架；测试使用隔离合成数据。远端 develop 合并继续按既有决定暂缓，仅 feature 推送。

## 目标与边界

2026-11-01用户收紧范围：保留已有H5 Agent入口，停止新增工具、偏好／主体／下载等能力入口。PC／H5共用后端适配、计费与任务结果，H5只对现有页面的差异做必要适配／验证，不逐工具重写或复制全部PC交互。批次73已撤回未推送的扩展；旧批次PC交互待补清单由此约束替代。

工具提供业务加工后的提示词、素材、模型选择及可信业务关联，共用模型请求准备、运行入口和版本化任务结果。新增同类已支持模型只修改声明／适配器；工具不再新增该型号专属运行分支。

复用 `MarketGenerationAdapterRegistry`、`MarketGenerationCatalogService`、`MarketGenerationRequest`、`PreparedMarketGeneration`、现有运行服务及 AiAppTask／AiConsumptionLog／AiTaskJob／AiTaskResultAsset。统一层委托已有预占和结算，不再创建平行计费或队列。各应用 API 路由和权限边界保留。

业务编排不合并：商品套图父子任务及应用售价覆盖、短剧意图／版本保护、微视频分段及方案确认、数字人专属资产／阶段、剪辑专用渠道继续由原工具管理。旧任务、旧task_id语义、冻结价格和资产库ID保持；统一结果资产ID使用独立字段，不能冒充业务资产ID。

## 实施工作及验收门槛

1. **统一调用**：以既有注册表为唯一运行路由，统一报价、预占、提交、查询的调用约定，保留每类协议最终校验。应用售价覆盖只接收服务端业务策略；不支持时明确拒绝，不得忽略或回退到便宜规格。
2. **统一结果**：新增版本化 `generation_task`，任务引用明确指向统一应用任务；读取必须验证租户、用户及业务关联，不能暴露管理端消费详情。执行／计费／转存状态分开；结果用受管资产身份、存储声明和解析后的展示URL，禁止将输入／参考URL识别成结果。读取仅使用本地持久记录，不产生供应商查询。
3. **业务回填**：统一处理器登记作为支持判断与分发的唯一来源；回填可重试、幂等、匹配当前任务／节点版本，缺处理器不能空成功。持久业务关联必须在供应商提交前建立。保留既有短剧意图和父子任务策略。
4. **工具接入**：原生图片／视频及画布首先进入共享调用和结果；相关图片应用与宣传视频复用底层路径，复合响应保留父状态，不能把首个子任务完成当成全任务完成。数字人、音乐等仅迁移对应已支持市场调用，保留旧渠道和专属流程。
5. **前端消费**：复用现有参数／报价层，统一任务状态、错误、结果读取及轮询生命周期。新结果使用明确task_ref；旧接口仅按其明确业务语义兼容，不用 `task_id || id` 推断新的统一任务身份。保存／历史重开继续兼容旧数据。
6. **贯穿验证**：先跑正常登录HTTP与同一隔离任务的提交、查询、worker、结算记录、转存、业务回填、保存重开；再验证代表性视频、两画布、单图片应用和多子任务应用。重复提交、失败、取消、转存未完成、旧任务冻结和跨用户隔离必须有针对性验证。供应商传输替身只能用于私有测试环境，正式配置不增加模拟开关。

优先补可复验的正常主线与必要回归；不以逐型号重复进程故障矩阵代替工具接入验收。既有正式合同、2像素／6Token等阻塞单列，不阻断合同已确认的工作，也不因接口收口自动启用。

## 交付标准

- 已接入工具使用统一调用约定及任务结果，旧API和业务任务不破坏。
- 同一最终模型请求、相同计价策略，在各入口的上游参数、SKU与冻结计量一致；应用零售价按其既有策略单独验证。
- 一次已接受任务可独立于页面存活完成，重复回填不重复收费／文件／业务结果，旧任务不被新默认改写。
- 每类工具明确记录已迁移、保留业务编排、尚未支持的能力及验证证据。没有真实收费生成，不能宣称全部供应商真实调用已实测。
- 完成相关工作后再统一报告完成／剩余、验证及两仓 feature 提交；不按小批次自行停工。
