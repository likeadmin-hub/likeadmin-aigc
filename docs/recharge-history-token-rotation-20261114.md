# 充值记录与虚拟支付凭据轮换

已确认一种“自定义充值显示、套餐充值不显示”的实际故障链：套餐使用微信虚拟支付，微信已付款，但订单冻结的小程序 AppSecret 失效后，查单与回调处理无法取得 token；本地订单与交付仍为 pending，因此成功充值记录不会包含这些订单。订单快照中的旧 AppSecret 与当前配置不同，但 AppID 相同；使用当前凭据只读查询原订单可验证原身份、金额及付款状态。

令牌请求现在允许同一租户、同一 AppID 使用当前非空 AppSecret，缓存键包含凭据摘要。切换 AppID 或当前凭据为空时继续保留原身份凭据；授权模式不变。原支付 AppKey、环境、道具、订单号与金额快照完全不变，不允许用新应用或新支付合同接管旧订单，也不直接修改历史加密快照。令牌失败只展示微信错误码，不输出密钥或原始响应。

另修复成功充值记录的独立显示缺陷：返回稳定订单 ID 和订单号、使用真实分页与一致租户用户过滤，区分到账算力和支付金额；旧订单没有冻结算力时继续按历史金额回退。移动端返回页面会刷新，旧会话或旧请求不能覆盖当前记录。该接口仍只展示真正完成交付的充值，不把未支付或未到账订单伪装为充值成功。

存量恢复须先向微信核对每笔原订单，校验 AppID、环境、金额、原订单关联、退款状态、冻结权益及现有流水。获得补交付授权后通过现有 reconcile / grant 服务执行，保留幂等锁和交易唯一性，不直接写余额、不再次扣款、不以“展示修复”伪造成功。现场查询授权与生产写入授权分开核对。
