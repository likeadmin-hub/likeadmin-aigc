# 短剧画布实施记录

更新：2026-09-15。

短剧画布是 `aigc_short_drama` 内的新增创作入口，不是独立应用，也不使用独立无限画布的业务、配置、任务或数据。既有短剧首页和传统创作提交流程保持不变；用户从首页现有画布模式进入新工作区。

## 已接入的业务边界

- 已启用短剧应用的租户默认可使用画布；没有第二份购买、上架或模型配置。
- 画布 Agent 使用短剧租户资源状态中的剧本策划文本模型，并通过短剧现有算力市场运行时创建消费与任务记录。画布不保存供应商密钥、不自定义价格、也不直接改积分。
- Agent 只能产生角色、场景、分镜草稿和待确认媒体提案。草稿不会在模型回合内直接改正式短剧。
- 用户确认“应用草稿”后，角色与场景调用短剧主体库服务；分镜调用短剧已有的新增/保存分镜服务。
- 用户确认媒体提案后，先由短剧现有估价服务生成报价，再创建现有短剧图片或视频分镜任务。模型、价格、余额校验、结算、重试、取消和结果查询都沿用短剧任务链。
- 未绑定项目的工作区可先保存和使用 Agent；用户明确确认“转换为短剧项目”后，创建标准短剧剧本任务并绑定工作区。该任务仍通过原短剧计划页面继续处理。
- 工作区布局、消息、草稿和操作记录仍独立保存；全局和分集视图只保存各自的画布布局。

## 稳定性约束

- 所有工作区、草稿、提案和短剧项目访问均按租户与用户校验。
- 画布回合、创建项目、草稿应用和媒体提交均使用请求键或版本确认，避免重复点击产生重复操作。
- Agent 回合串行、最多八项白名单工具调用；Worker 使用租约执行，未知上游提交进入待核对而不自动重发。
- 媒体生成前必须展示并确认由短剧资源状态计算出的参数和报价；画布本身不绕过短剧的 Skill、阶段或余额校验。
- 删除画布节点只删除画布引用，不删除短剧主体、分镜、任务或文件。
- 强制只读可用于维护；不会删除工作区，也不会影响既有短剧入口。

## 接口与前端

画布路由：`/ai/short-drama/canvas/{workspaceId}`。

除工作区、布局、消息和附件接口外，新增以下明确确认接口：

| 动作 | 结果 |
| --- | --- |
| `createProject` | 创建并绑定标准短剧剧本任务，返回原短剧计划页地址 |
| `previewDrafts` / `applyDrafts` | 先预览，再写入短剧主体库或项目分镜 |
| `quoteProposal` / `submitProposal` | 先按短剧规则报价，再创建标准图片/视频分镜任务 |

PC 画布侧边栏展示转换项目、应用草稿和确认媒体生成入口；预览环境不调用这些正式接口。

## 参考流程对齐

画布基于公开可观察到的同类创作流程完成交互对齐，没有读取或复制第三方私有前端或服务端代码。短剧画布按以下顺序呈现同一条可审计链路：

1. 创作配置：单集、比例、时长仅填入 Agent 输入，不会自动提交。
2. 剧本与分镜：Agent 回合只生成短剧画布草稿，并在画布上呈现剧本、角色、场景和分镜关系。
3. 美术资产：画风入口只预填创作要求；图片、角色三视图和场景资产先以候选提案显示。
4. 媒体生成：必须复用短剧任务链的模型、规格、报价和确认；未确认不出站调用付费媒体任务。

侧栏保留执行轨迹，显示工作区创建、Agent 排队/完成、草稿生成、项目绑定、草稿应用和媒体提交等短剧自己的事件。未实现的高级能力保留为候选提案或明确入口，不伪造生成完成状态。

Agent 草稿和用户布局是两份数据：刷新时，草稿以只读派生节点和虚线关系展示；用户首次拖动、编辑、连线、复制或删除时才将该节点材料化为版本化布局。这样既保留画布操作，又不会因刷新或另一个标签页保存布局而静默覆盖数据。

## 已完成验证

1. PHP 语法检查覆盖画布服务、Worker 与控制器。
2. 独立 SQLite 存储测试通过 113 项：工作区幂等、租户/用户隔离、附件、布局冲突、工具白名单、租约恢复、只读和分集视图。
3. 隔离 MySQL 并发测试曾验证 20 个同键并发创建仅产生一个工作区和一条后续消息；该测试不调用模型或付费渠道。
4. PC 组件契约测试通过：入口、附件、会话标识和串行保存冲突保护。
5. 已对真实短剧工作区执行刷新回归：角色、场景、分镜草稿可在刷新后恢复显示，布局状态保持“已保存”，不再触发草稿投影造成的版本冲突。
