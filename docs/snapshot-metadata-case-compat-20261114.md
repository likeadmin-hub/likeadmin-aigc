# 快照容量迁移大小写兼容补查

2026-11-14，本地 PHP 8.2 / MySQL 5.7.44 验证。

历史 1.0.430 ZIP（包括本地 verified 归档）仍使用“缺少原字段”直接终止的实现。`7e33bd8b36` 于 11 月 8 日补齐真正缺失的快照字段，该代码在本地 1.0.435 ZIP 中与当前基线相同。后续增量包未携带该文件时，不能修复仍停在 430 的失败步骤。

临时表复现发现，旧修复尚未覆盖大小写差异：实际字段为 `PRICE_SNAPSHOT` 时被原字段名严格比较拒绝；驱动将结果键转为大写时，SQL 模式元数据读取失败。这证明实现仍有兼容缺口，但两个错误与客户旧包的错误文本不同，不能认定客户现场根因已经查明。

补丁只将查询元数据键规范为小写，按 MySQL 字段名规则进行不区分大小写的等值校验，并使用实际字段拼写生成扩容 DDL。字段名、NULL、默认值、字符集、排序规则、注释和 EXTRA 校验仍有效；不构造缺省字段元数据、不跳过多行歧义、不修改历史 SQL。真实临时表回归覆盖大写字段、大写返回键及组合，检查重复执行和原始数据保留。

本次仅交付本地源码，不替换已签名的历史归档，不发布版本，不操作客户数据库或失败回执。客户截图中的“SQL 结果未知”仍需逐站核对实际连接库、表前缀、全部目标字段、包 SQL 和回执后制定恢复步骤，禁止自动重放或伪造完成状态。当前仅有“客户的”这一标识，无法定位具体站点。
