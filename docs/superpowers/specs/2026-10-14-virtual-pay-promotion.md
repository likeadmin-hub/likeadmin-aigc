# 微信小程序虚拟支付与套餐优惠规格

权威：用户批准本会话方案并要求直接实现、完整测试、合入本地 develop；不推送、不发布，真实扣款/退款跳过。文档把已批准规则固化，不引入第二次批准流程。

## 范围与规则
- 算力与会员套餐；PC/H5/小程序共用后台优惠。小程序虚拟支付支持 iOS/Android；AI调用保持原算力计费，OEM保持原入口。
- 租户财务/套餐管理新增虚拟支付配置；每租户实际有效小程序 AppID 独立 OfferID/密钥；默认关闭。现有手工/开放平台授权双模式均支持。有效小程序更换后原交易仍按原身份核对；新配置不可跨 AppID 复用。
- 道具直购、CNY、数量1；常规与优惠道具按套餐、购买周期、AppID及环境绑定。缺少映射阻止小程序支付，保存≠支付能力已验证。
- 金额按分，界面返回两位小数字符串；普通售价/划线价/优惠价分别保存。优惠>0且<普通价，划线价≥普通价。小程序 iOS 适用金额≥1元。
- 新人优惠：注册时间+N小时；全体优惠：首次保存启用时起统一N小时。两规则 OR，但单个用户/租户/业务类型/套餐仅成功享受一次优惠，跨端、周期、活动重启共用次数；常规购买不消耗。复制为新套餐是独立商品。
- 默认优惠关闭、默认时长48小时。普通保存不重启全体活动；显式重启写新版本但不重置次数。
- 计价在后台；价格变化时要求用户确认新报价。建单原子预占优惠并冻结价/权益/规则；建议订单锁价30分钟。过期取消释放前核对渠道，结果不明继续持有。付款确认消耗一次；退款不自动恢复次数；发货失败重试原订单。
- 前端成功不证明支付/交付；只可信验签通知/服务端查单，核验 AppID/用户/环境/业务单/产品/币种/数量/金额。支付尝试有独立渠道单号，重复付款另记；iOS不可承诺开发者主动退款。
- 后台保存 AppKey 加密不回显；session_key 仅服务端，有效身份绑定。签名 JSON 字节原样传输。沙箱与现网独立；iOS仅现网，检测客户端能力及官方条件。
- 支付、权益发放、渠道发货、退款是独立状态。事务中复用算力/会员发放服务，订单唯一发放。虚拟支付成功响应只在核验及权益发放成功后返回；异常落库并查单/notify_provide_goods补偿。
- 通用发货管理独立适配，检测管理服务、订单范围及真实交易标识；虚拟商品/统一发货。核对已发货避免重复上传；不可把Apple订单伪造成微信交易。确认收货组件回传后服务器再核对。
- Android退款先查后提交固定退款单号；结果未知先查原单。iOS处理退款问询/通知且不主动调用退款；未消费权益核对后回收，已消费/冻结/叠加会员或无法归属进入人工核对，不动正在运行任务及无关权益。投诉/风控通知记录后台待处理。
- 保留旧订单/原支付流程。静态追加迁移支持安装、升级、新租户菜单与重复执行；生产无跳过验签/模拟支付入口。

## 验收
纯规则、实际SQL/认证/支付适配/通知控制器/故障恢复/并发优惠预占；PC/H5/小程序客户端、租户界面、iOS/Android差异；菜单及迁移重复执行；会员充值/OEM及运行任务保护回归；后端语法、三端既有自动测试、PC/租户/平台/H5/小程序正式构建。真实扣款/退款明确SKIPPED，iOS无沙箱，模拟不等于真实支付验证。测试入口和数据只在 loopback/oem_* 隔离环境。

官方依据：微信虚拟支付、wx.requestVirtualPayment、xpay查询/退款/发货、通用订单发货管理文档（2026-10-14已核对）。
