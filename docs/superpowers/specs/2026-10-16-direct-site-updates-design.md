# 1.0.403：恢复站点原目录更新

## 已确认的目标

用户要求把小程序发布状态恢复、租户优先的平台域名判断、运行时存储整改一起发布，并同步前后端 develop/master。普通 PHP 站点直接执行站点目录里的 app/config/route/extend 和 vendor；vendor 有升级时整体替换，无需为每次更新保留完整依赖或应用快照。不引入依赖共享仓库、硬链接版本库或另一套长期运行目录。

## 当前代码事实

- SystemPackageUpdateService::apply 无条件调用 ComposerRuntimeUpdateService::apply，并设置 immutable_code。
- 即使包未声明 composer_runtime，该管理器仍复制当前完整 vendor，然后复制 app/config/route/extend，生成一个 release-*。
- 被替换的共享文件另存 backups，包括前端完整目录。
- 应用更新在存在 current.json 时也会生成整套运行时。
- runtime-loader.php 使用 current.json 选择真正执行的代码；仅删除目录或仅修改根目录会破坏现有站点。
- RuntimeRetentionService 的进程枚举包含整台机器的 PHP，其他站点可能使清理持续延后。

## 正常更新行为

1. 保持现有签名、精确前驱版本、授权和路径保护校验，重新从原始已验证压缩包提取。
2. 使用现有本站任务影响判断；涉及后端或依赖时检查本站任务排空。HTTP 更新窗口必须有本站维护/读写互斥，现有请求退出后才替换可执行文件；不停止其他站点。
3. 按包更新正常站点路径。应用代码不再进入 generations。前端仍按 full_replace_dirs 整目录替换。
4. 依赖没变时不复制、不备份 vendor。依赖变化时验证完整匹配的 vendor/composer.json/composer.lock；暂存完成后整体替换 vendor，移除旧依赖残留。不得把新旧依赖混合合并；不得在客户站点联网执行 Composer。
5. 回滚工作区放入本站 runtime 的本次更新临时目录，只保存实际替换/删除的内容及原先不存在的路径清单。vendor 变化时只保留该次所需的一份旧 vendor，成功后删除。
6. SQL 延续既有幂等及执行日志规则；SQL 中断结果未知时停止自动重放。文件恢复不得伪装成数据库已回滚。
7. 元数据及版本标记仅在最后成功事务完成后推进。成功、失败恢复完成后清理本次临时副本；中断时保留必要恢复资料并明确状态。
8. 系统更新和应用更新均使用同一站点更新互斥，不能并发替换代码或依赖。

## 已使用旧运行时的站点

- 迁移以 current.json 指向的有效已提交版本为来源，不能假定站点根目录是最新代码。
- 先确认没有待恢复升级和不确定 SQL。任何指针、目录、版本或任务绑定异常均停止迁移，不能删除原目录。
- 1.0.402 的旧更新器已经固定使用 generations，不能让它假装理解新机制。1.0.403 的首次升级需保留其一次过渡调用的兼容性；使用真实 402 更新链验证新版本完成阶段将最终代码与完整依赖安装回正常目录。
- 新 HTTP/CLI 入口在迁移成功后从正常目录启动。旧更新器的完成、丢失响应后确认和失败恢复仍需可用；不得提前切换入口或清除其恢复证据。
- 清理历史 .composer-runtime 前，验证后续入口不再依赖它，并确认旧请求、子进程及任务已退出。仅依据本站实际读者/锁判断，不能因其他站点 PHP 进程而长期阻塞，也不能强行绕过仍在使用的旧版本。
- 已登记读者保护缺失或站点归属无法确认时，保留原目录并报告待处理原因；不能声称已完成空间回收。
- 新安装、迁移完成后的普通系统更新、应用更新均不得再创建 .composer-runtime。

## 兼容范围与包规范

- 保留 1.0.116 桥接和后续精确逐版本升级规则，本次为 1.0.402 -> 1.0.403。
- 现有 composer_runtime 包字段可作为完整依赖载荷传输格式继续兼容；它不再代表安装后创建同名运行目录。
- 403 安装包和完整服务端仓库必须具有同一最终运行行为；前端源码与服务端仓库继续分开。
- 归档签名、删除清单、前端完整替换、内置应用元数据和保护路径规则保持生效。
- .env、config/install.lock、上传文件、业务素材、任务数据、其他站点与无关工作区文件不进入替换或清理范围。

## 必须验证

- 无指针的新安装；连续两次普通代码升级均不创建 .composer-runtime，也不复制 vendor。
- 完整依赖升级与依赖回滚：匹配锁文件、删除过期依赖、自动加载和服务发现正常。
- 真实 402 运行时站点 -> 403 正常目录：当前有效代码、依赖、配置、路由、版本标记一致。
- 回滚前后 HTTP、CLI、延迟自动加载和应用安装/更新行为。
- 复制失败、元数据拒绝、SQL 中断、进程退出、完成响应丢失和恢复重试。
- 在途请求/本站任务的保护；其他站点进程不阻塞本站维护；不发送全局 PHP/FPM/Supervisor 信号。
- 成功后实测临时目录与历史目录占用，核验没有继续生成完整副本。
- 原有域名隔离与小程序发布恢复回归，所有端构建、包签名、在线发布记录与远端分支一致性。

## 当前发布状态

1.0.403 发布工作区已保存原两项修复、版本元数据和前端源码伴随说明。PC、租户端、平台端、H5、小程序源码构建已通过；尚未打最终包、上传发布或推送。运行时整改已实施，正在完成回归与正式包验证。
