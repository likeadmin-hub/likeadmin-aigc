# 应用安装修复与客户真实验收

## 已确认的根因

客户 `api.ysqyy.top` 系统为 1.0.411，PHP CLI/FPM 8.2.35，站点目录 `/www/wwwroot/api.ysqyy.top`。本次通过客户 Chrome 宝塔与应用市场实际操作核验。

最初失败任务 38（音乐 1.0.2）、42（剪辑 1.0.1）、51（短剧 1.0.15）均提示历史 `migrations/install.sql` 字节改变。随后重试才提示“上次 SQL 执行结果未知，禁止自动重放”。包文件 SHA256 和内部签名均正确；不是解压命令缺失或文件损坏。

客户磁盘实际已带音乐 1.0.4、剪辑 1.0.0、短剧 1.0.30，但音乐、剪辑没有安装登记，短剧登记仍为 1.0.3。部分云端包的历史 SQL 落后于当前系统迁移基线，其中音乐、剪辑签名与仓库 `2acf44753` 前内容一致。用旧云端包安装不能覆盖当前系统的历史 SQL；原预检没有提前检查完整候选环境，执行失败后留下保护回执。

## 系统修复

- 应用市场识别“磁盘已有代码、尚未登记”和“磁盘版本较新”；提供本地安装、同步本地版本，复用预检及原子安装流程。
- 本地快照严格校验应用路径、元数据和历史 SQL；使用系统交付的确切文件，历史基线迁移只接管不重放。
- 云端安装及更新以磁盘版本和登记版本的较高值为下限；旧版本和历史 SQL 不匹配提前拒绝。
- 预检检查 PHP CLI、子进程能力、元数据事务、全部迁移及旧回执。候选检查通过后才标记 SQL running；保留首错和执行绑定。
- 预检发现本站守护或任务仍在运行时，提示等任务结束、暂停本站守护和相关计划任务、重新预检，完成安装后恢复守护。
- 保留已存在租户的购买、启用、上下架、到期时间及更新时间；默认应用按既有规则为原先缺失的授权补齐记录。
- 前端失败持续展示原因并禁用本轮执行按钮；本地和云端操作互斥，较旧云端版本禁用。

后端已合入本地 develop，功能提交包括 `3a70e88bb`、`c0e262372`、`48cd03bab`、`e06aaec79`、`ddbc82b44`、`b0175d4a8`、`6dcb4b5a7`。前端包括 `6fba02cd`、`07ef8b8d`、`991d8673`、`a43dd5fc`。未推送远程 develop/master，未发布全客户正式系统版本。

## 其他客户处理步骤

1. 备份站点、数据库和更新回执，记录首次失败，不清空 SQL running 或未知回执。
2. 部署包含本次修复的匹配系统版本，查看应用市场本地磁盘版本、登记版本和云端版本。
3. 磁盘已有当前系统交付的完整应用时，选择本地安装或同步本地版本；只有兼容且更高的云端版本才使用云端更新。
4. 等待现有任务结束，暂停本站任务守护及相关计划任务，重新预检并安装。按具体环境提示处理，不为解压盲目放开所有 PHP 禁用函数。
5. 安装后核验应用状态、版本和任务 success，恢复本站守护并检查工作进程。核对已有租户权限、业务数据和历史回执。
6. 真正执行结果未知且没有兼容本地代码的客户，保留保护并核对表结构、执行日志及迁移记录，制定针对性恢复方案；不得整包重跑历史 SQL。
