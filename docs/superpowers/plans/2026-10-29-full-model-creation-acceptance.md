# 全文本模型剧本与 Agent 真实验收实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全部文本模型逐一通过完整单集、多集剧本生成与所有现有 Agent 对话应用；图片、视频各选一个模型跑通业务全链路，修复后全面测试通过才交付。

**Architecture:** 在现有页面、业务 API、队列/worker、协议适配、素材和账单链路上验收，不另建创作流程。冻结模型渠道清单，按模型×场景×应用登记真实任务与结果，离线回包测试、真实上游生产、UI体验和账本核验分开报告；失败不静默换模型、不删出覆盖分母。

**Tech Stack:** 现有 ThinkPHP/PHP 运行时、Nuxt/Vue PC 与现有 H5、现有任务队列及模型协议；验收编排拟用 Node.js 原生 HTTP 客户端，仍经现有业务接口，不直连供应商绕开系统。

**Spec:** [总体方案](../../short-drama-canvas-flow-optimization-2026-10-29.md)、[剧本专项](../../short-drama-script-reliability-plan-2026-10-29.md)、[费用专项](../../short-drama-canvas-billing-audit-2026-10-29.md)、[新增客户反馈专项](../../market-pricing-and-drama-image-feedback-plan-2026-10-29.md)，以及用户本次“所有文本模型、单集多集、所有Agent应用；图视频各一个；全面测试通过”的要求。

本文件为**待执行计划**，本轮只更新方案，未实现测试脚本、修改业务代码、启动生成任务或发生模型费用。下列拟建路径、命令和检查项不代表文件已经存在或测试已经通过。

## Global Constraints

- 全部对外提供的文本模型都列入清单，官方与三方均逐项测试，不限制测试模型数量，不用抽样代替全覆盖。
- 不设测试累计金额、Token、总调用、总重试、总耗时等人为停止线；取消业务内部累计封顶，不能测满固定数量便结束。单次请求真实能力、调度时间片、限流、权限、余额和用户取消仍按原规则处理，时间片结束自动续查/续处理。
- 单集、多集生成完整剧本，不能只测试问候、文本接口200、故事梗概、大纲、第一集或空壳JSON。
- 每个文本模型都在所有现有 Agent 对话应用真实对话；共享底层服务不能代替各应用的工作区、会话、参数传递和回写验收。
- 图片只需一个模型，视频只需一个模型；使用它们贯穿现有业务链路，不扩成全部媒体模型，也不为每个文本模型重复跑付费媒体生成。
- 费用沿原用户承担、租户平台成本账及价格快照处理；原本免费的步骤继续免费，不新增承担方、预算、prompt表单、创作步骤、生成方法或收费确认。
- 每个未测、失败、外部阻塞都如实报告；禁止静默换模型、下架失败模型、缩小集数、删除场次或伪造回执以凑通过率。

## Review Focus

1. 同名模型不同渠道/协议或输入输出SKU组合，实际被默认模型替换后仍被误算通过。
2. 多集只产出大纲/前几集，返回success但集/场/镜头/人物场景引用或用户明确事实缺失。
3. Agent能回答问候，但多轮、工具协议、停止恢复、工作区隔离、历史会话或文本回写失败。
4. 模型格式/流式事件差异引发空回复、reasoning冒充正文、工具结果遗漏、重复展示或PHP类型异常。
5. 超时后实际已受理、格式恢复或素材转存失败触发重复生成/扣款，或费用状态被父任务失败覆盖。

## 1. 全覆盖清单与分母

模型身份至少登记：平台商品ID、model_code、渠道ID/code、官方/三方、协议、可用输入/输出SKU组合、租户上架状态、应用实际可选项、模型能力与目录版本。同名不同渠道分别测试；输入/输出计费SKU作为一次调用的配对记录，不能误算为两个独立模型，也不能合并真实不同的路由/运行规格。

先盘点平台当前全部对外提供的文本模型，再与授权测试租户目录、短剧和各 Agent 选项交叉核对。租户未上架、缺凭证、目录遗漏或接口不支持均记录为前置缺项/阻塞，不能从分母静默删去；不得擅自改客户上架、密钥或生产价格来完成验收。真实已下架/非生成类 embedding/rerank 等记录分类理由，不冒充已通过生成测试。

普通纯文本输入是所有文本模型的共同必测基线。视觉附件等真实能力附加场景按能力验证；纯文本模型不强求原生看图，但不能以“不支持视觉”为由跳过剧本和基本 Agent 对话，也不能用视觉路由自动换模型后的成功代替原模型通过。

执行前冻结清单版本；结束前对比目录，新增或路由变化项补测。数目来自实际目录与路由，不在方案中编造模型总数。测试并发只控制速率与资源，队列需处理完全部清单；不能用并发数、批次大小或单轮时长作为覆盖上限。

## 2. 强制真实测试矩阵

| 编号 | 范围 | 必测路径及通过标准 |
| --- | --- | --- |
| T01 | 每个文本模型 | 用户选模型→创意→现有故事/大纲→单集完整剧本→场次/分镜与人物场景资料；能保存、刷新恢复、编辑、继续制作，原明确事实完整 |
| T02 | 每个文本模型 | 3集多集完整生成，三集均有正文和既有要求的场/镜/引用，集序准确，跨集设定连续，不以全剧大纲代替各集剧本 |
| T03 | 每个文本模型 | 在现有产品允许的范围逐步执行10集、20集长多集用例，覆盖原内部累计阈值和多轮dispatch，全部目标集完成且不改时长/镜头方法；1/3/10/20是用例，不是上限 |
| T04 | 每个文本模型 | 原有导入与局部修改路径，保持明确台词/事实及未修改范围；可选复核开/关均不跳过基础结构校验；已有受理回执和已通过集不被重生成 |
| A01 | 每个文本模型×每个Agent应用 | 新会话首轮、带上下文追问、明确修改、历史恢复后继续；正文可见非空、上下文正确、实际模型与选择一致，未发生默认模型偷换 |
| A02 | 每个文本模型×每个Agent应用 | 原应用已支持的计划/文本/资料读取工具调用与回写；工具参数/返回/调用ID完整，结果不是reasoning或内部JSON；有原确认时按原确认执行 |
| A03 | 每个文本模型×每个Agent应用 | 原有流式/后台事件、刷新重连、停止及允许的恢复、重复消息防重、工作区及租户用户隔离；不跨应用读写素材/会话，不自动执行历史未确认收费动作 |
| M01 | 一个图片模型 | 单集和多集已完成文本结果→策划页主体/场景图→既有工作台/画布图片路径→上游真实结果→转存/显示/复用及账本对应；覆盖本次prompt问题 |
| M02 | 一个视频模型 | 现有分镜/画布路径，按原首尾帧或参考策略生成真实视频→任务查询/回调→转存→播放和既有成片/导出路径，费用与素材归属正确 |
| C01 | 公共业务 | 音乐多API定价保存、部分失败、平台/租户并发改价、上下架保价、死锁恢复、成功后刷新失败；无虚假整体成功及旧价覆盖 |
| B01 | 所有真实调用 | 任务、模型、渠道、消费、usage、预占/结算/退回/待核对关联；本地解析、读取和回放不新扣费，用户/租户账符合原规则 |

T03遵守原有实际产品输入范围。若现有合法范围不足某个用例集数，登记原规则与对应覆盖替代，不能为测试新增产品限制或改创作方法。长输入超所选模型单次真实容量时仍沿原分段/续写方法测试，不能通过减少目标集数假通过。真实外部能力或持续服务异常使合法目标不能完成时，该项保持阻塞，不宣称全模型已通过。

Agent应用清单至少包含：`aigc_llm` 通用Agent对话、`aigc_canvas` 独立画布会话、`aigc_short_drama` 短剧画布对话。实施前继续从应用清单、路由、前端入口和运行时查漏，发现其他已启用 Agent 对话应用即追加。微视频、智能文案等若只是文本生成不冒充Agent；其调用公共文本链路仍纳入原业务回归，若实际提供Agent对话则加入全模型×应用矩阵。

本地源码当前 `MarketTextModelRuntimeService::resolveAgentModel` 只允许 `openai_chat / anthropic_messages / openai_responses` 工具协议。该限制必须在矩阵中显式暴露：其他对外提供的文本模型不能仅凭普通聊天通过就宣布Agent兼容，也不能缩小目录隐藏缺口。优先修复现有协议适配和消息/工具参数兼容，不替换Agent框架或生成方法；真实供应商不具备所需能力则如实列阻塞，不伪造原生工具支持。

## 4. 分任务执行步骤

### Task 1：清单、应用和模型身份对照

**Files:** 上述拟建编排脚本、用例模板、清单测试；读取现有市场文本目录、应用配置及前端目录，不先改上架策略。

**Interfaces:** 输入平台/租户/应用实际目录；输出不可遗漏的manifest及缺项清单，供后续用例和报告使用。

- [ ] 建立清单测试：同名不同渠道保留、输入输出SKU配对、目录遗漏和未测项无法算通过。
- [ ] 显式运行该离线测试，确认新规则尚未实现时能暴露遗漏，再实现清单校验。
- [ ] 只读盘点真实模型/应用、选择授权测试身份和环境、记录server/web/worker版本及原价格；不得启动有历史积压的未知worker。
- [ ] 比较平台、租户、各应用选项及真实协议；缺上架/密钥/协议形成阻塞项，不静默换模型。
- [ ] 离线测试通过后只提交本任务文件，并按仓库规则合入本地develop。

### Task 2：逐模型完成单集与多集

**Files:** 编排脚本、用例模板；已有剧本解析/修复/规划单元测试及专项列出的生产文件按缺陷最小修改。

**Interfaces:** 输入manifest模型身份与固定场景；输出每集完整性清单、真实任务/回执引用、原模型身份和费用关联。

- [ ] 先以离线回包覆盖subjects、数组转换、截断、流式、格式/引用差异；复现缺陷再做最小修复。
- [ ] 在本地develop核对队列与worker版本后，通过原业务接口对每个模型执行T01、T02，并逐模型推进T03、T04；模型清单全部完成，不设抽样名额。
- [ ] 每一步核对实际路由模型、已确认剧情/角色/场景、集号、场/镜/对白及引用，不只检查success或JSON可解析。
- [ ] 失败定位到输入/模型回包/解析/持久化/调度/费用环节，修复后重测失败项及受影响原成功项，保留修复前后报告。
- [ ] 校验原回执和已完成集没有被覆盖；受理不明先查询；合格结果保留，不能以换模型/缩剧集代替修复。
- [ ] 通过后提交对应缺陷及定向测试，合入本地develop并更新待测版本；共享逻辑变动使受影响全模型用例重新待验。

### Task 3：逐模型完成所有 Agent 应用

**Files:** 同一编排脚本和模板；现有 `AgentExecutionService / MarketNeuronProvider`、独立画布会话、短剧 `MarketTextConversationProvider / ConversationService` 及各自定向测试按缺陷修正。

**Interfaces:** 输入模型×应用manifest；输出每会话/轮次/工具/回写证据，不以共用provider一次通过覆盖全部应用。

- [ ] 建立协议事件/正文/工具结果/工作区隔离的离线回归，未知工具协议及空正文不得PASS。
- [ ] 对每个模型在每个应用执行A01—A03，含真实多轮回复、文本或资料工具、原有确认、刷新恢复及取消。
- [ ] 测试中文、长上下文、普通与推理型结果、工具参数/流式增量；正文显示与服务器持久化一致，不展示reasoning代替最终回答。
- [ ] 只在实际支持的附加场景验证视觉能力，不强迫纯文本模型看图，也不借附件路由偷偷替换已选模型后算通过。
- [ ] 媒体工具规划可在原确认节点检查参数；每个文本模型不重复执行真实付费图视频。纯文本/工具协议验收与实际媒体执行证据分开，不能把未执行工具称为执行成功。
- [ ] 修复后回归该应用和共用运行时影响范围；按仓库规则提交与本地集成，不以隐藏不兼容模型交付。

### Task 4：一个图片模型和一个视频模型端到端

**Files:** 编排脚本的媒体场景、已有策划页/工作台/画布及共享图片视频运行时的相关定向测试。

**Interfaces:** 输入已通过的单/多集文本结果及固定一个图片、一个视频模型；输出真实素材、可播放结果、存储与费用证据。

- [ ] 图片选择当前合法可用模型；若Qwen Image 2.1可用优先用其复现新增prompt反馈；不可用如实列出现场验证缺项，不伪造已覆盖。
- [ ] 先通过离线回归覆盖平面/结构化协议与缺prompt分支；真实只需上述一个图片模型执行M01，不扩大为全部图片模型。
- [ ] 用一个视频模型按原方式执行M02；检查实际数量、画幅、时长、参考素材与价格，不替换既有首尾帧/多参考策略。
- [ ] 完成上游真实输出、转存、图片显示、视频播放、画布回写、原合成导出及账本核对；返回任务ID或单张截图不足以算跑通。
- [ ] 同一模型用于相关现有入口与失败恢复，不要求每个文本模型重复生成媒体；恢复查询不重复扣款。

### Task 5：配置、资金、异常与体验回归

**Files:** 定价/费用专项指定文件和定向测试；现有PC/H5/平台/租户页面，运行时证据目录。

**Interfaces:** 输入全部已发生任务/消费及原配置快照；输出C01/B01报告和回归问题清单。

- [ ] 先运行纯本地配置事务故障测试，验证死锁、部分提交、旧价覆盖及提示一致性，不包住收费调用重试。
- [ ] 覆盖刷新/断线/重复提交、worker重启、多轮dispatch、原累计门槛、received恢复、结算或转存失败；故障注入仅限隔离环境，不杀客户运行任务。
- [ ] 逐项关联用户零售价、租户平台成本、真实usage与原流水；区分预占、已扣、退回、待用量和待核对。上游受理后本地失败不全退，不按toast推断费用。
- [ ] 在真实视口检查模型官方/三方标识及排序、当前选择保留、详情/复制、剧本和Agent输出可编辑/可继续、海量列表及菜单可操作。
- [ ] 运行原正常业务回归和必要构建，不扫描会产生顶层副作用的全仓测试；完整记录未测范围，不能用旧118/68测试记录冒充本轮全面验收。

### Task 6：全量复核与交付门槛

**Files:** 验收报告与证据索引、上述所有关联方案；不为通过率改生产上架/模型选择。

**Interfaces:** 输入全部逐项结果及最终版本；输出能够复核的最终报告，未通过清单保留。

- [ ] 状态严格区分 `PASS / FAIL / BLOCKED / NOT_RUN`；只有带实际完整结果及证据的用例可PASS，不能用重试次数或首次失败率代替最终业务完整性。
- [ ] 按模型×渠道列出单集、各多集用例、每个Agent应用，以及各一个图/视频模型真实全链路结果；另外报告首轮成功率、恢复后结果、耗时、调用与费用。
- [ ] 最终变更后重新比对模型目录、应用清单及worker版本；新增模型补测，共享逻辑改变时重跑受影响矩阵，旧版本通过不能自动继承给新版本。
- [ ] 全部强制文本/Agent及媒体、配置、费用、兼容用例PASS才称“全面测试通过”；任何阻塞/未测均明确列出，不能合并成成功。真实外部不可用可保留恢复能力，但不能宣称该模型已跑通。
- [ ] 输出缺陷→修复commit→回归用例→任务/回执/素材/账单证据链；保留原失败记录，不只展示最后成功截图。

## 5. 报告格式与执行状态

逐项报告至少包含：run_id、case_id、模型/渠道/协议/SKU、应用和工作区、server/web/worker版本、目标集数与完成集数、任务/消费/上游回执引用、输出/完整性检查、原选择与实际模型、真实状态、首轮/恢复记录、耗时、usage、用户费用与租户成本、问题和证据路径。密钥、token及签名URL不得进入普通报告。

完成率分母来自冻结且结束时复核的清单。外部阻塞、协议未适配、未测分别统计，不能从分母扣掉再报100%；按能力确实不适用的附加项需独立列出理由，不能豁免共同必测项。图片/视频清单按用户要求各一个模型，不为追求数量扩大范围。

当前所有执行复选框均为未完成。仅本计划及交叉引用更新；尚无全模型数量、真实测试结果或测试费用，实施完成后须按本矩阵实际执行并提供证据，不能提前承诺已经全面通过。
