# Natural script revision contract

New script-message submissions opt into `ShortDramaRevisionAgent::VERSION`. Existing receipts and historical requests retain their original execution path. Story planning, editable episode outlines and episode production all use the same new protocol; the production-backed canvas adapter delegates to it as well. Legacy canvas workflows retain their frozen compatibility path.

The agent receives the authorized current plan, up to eight prior revision turns, a catalog of owned versions, referenced subject identity facts, the current stage and the tenant's shot-duration rule. It proposes bounded, typed operations; it cannot write SQL, URLs, task identity, pricing, permissions or storage. Plain questions and ambiguous requests return a conversational reply without creating a plan version or canvas nodes. A failed edit acceptance also returns an explicit not-applied reply and retains the baseline.

Supported operations include field updates, entity insertion/removal, subject/location/shot merges, shot splits and ordering. Subject/scene/shot references and stable IDs are checked after the whole operation group, so dependent changes apply together. Story and outline stage boundaries remain enforced; an episode edit cannot modify other episodes. Bound library identities cannot be rewritten. Removing a binding only affects this project. Restore resolves only an owned version in the frozen catalog and saves a new version rather than deleting history.

Canonicalization fills missing production fields only for changed/new objects. Unchanged authored objects, prompts and narrative ordering are preserved. Independent semantic acceptance runs against the final canonical result, including actual prompts. Mechanical acceptance checks structural validity, references, configured duration bounds and any declared quantity/language goals. Replies contain changes calculated from the actual result rather than the editor's claimed success. This is edit acceptance, not a claim that all cross-episode continuity has been reviewed.

Editorial continuity review is optional. Normal generation, edits, merged drafts and episode advancement do not schedule it, even when a historical request stored `quality_review_enabled=true`. Only an explicit `review_content` action uses the dedicated review pipeline; a conversational request to check the supplied story returns concrete findings without editing it unless repair is also requested. Manual findings are advisory and do not block later episodes. Historical automatic `needs_review` notices are projected as unreviewed without rewriting saved versions or provider receipts. Structural validity, references, stage confirmation, cancellation, provider failure recovery and actual edit acceptance remain enforced.

The existing durable planning-unit and text billing path executes editing and independent acceptance. A successful edit normally has two text-model calls; questions, clarifications and mechanically rejected edits need only the first call. Received responses replay without another provider submission. No image, video or audio generation is triggered by a text edit. Media impact identifies affected shots without deleting or replacing assets. Historical assets retain their provenance and real generation parameters.

Existing message, detail and project-detail endpoints are reused. Project detail adds `revision_turns`; results add `revision_response` (`action`, `edited`, `message`, `changes`, `media_impact`, `base_task_id`). No terminal task status, route, permission or database schema changes are required. No-edits replies have no generated-document card, survive refresh and remain available as context for the next instruction. The frontend saves pending manual storyboard edits before submitting a new message and sends a submission key for transport idempotency.

Production settings remain bounded by the existing application/model controls. Aspect-ratio and audio preferences affect future generation only. Image resolution is still owned by the sellable generation specification, and model switching uses the existing picker; a request to override these in the script conversation is explained rather than falsely reported as applied. Existing confirmed outlines cannot be silently reopened across production stages.

Validation uses offline editor/acceptance responses and transactional fixture receipts, never an unrequested paid provider call. Coverage includes collection reduction, dangling references, multi-object merges, English with named speakers, video sound-line synchronization, structural shot edits, stable ordering across later reads, independent rejection, no-op detection, stage isolation, bound identities, owned version restoration, empty-subject films, canvas dialogue restoration, billing, idempotency and durable replay. Source-only rollback is to disable opt-in for new submissions; keep saved response/projection fields readable so accepted historical versions remain immutable.
