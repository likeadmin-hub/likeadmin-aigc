# 批次33：更多图片应用历史与两类画布混合分组

本批完成三类图片应用的四次正常登录历史重开、七份旧子任务的冻结输入交叉，以及普通画布／短剧中的混合分组替换、删除、重开。发现并修复三处代码缺口。没有收费生成、再次生成／重试、供应商任务或供应商资产调用；原任务、原用户项目未改写。正常 HTTP 的保存变更仅限既有授权的两个隔离合成项目，测试后已撤销并重开核对。整体适配仍未全部完成。

## 修复与回归范围

1. 13 个图片应用同步子任务事实时无条件刷新父任务 update_time，旧终态的 finish_time 也可能被缺失／较晚的子任务时间改写。统一接入 ImageAppTaskSync：终态未变且已有完成时间时保留旧值；只有事实确实变化才保存；真实 running→failed 迁移仍更新。各应用原有聚合状态、费用与结果补齐逻辑保留，没有跳过所有终态。13 组新合成父子记录完整回滚；缺失时间、迟到时间、重复同步、真实迁移都经过实际服务验证。
2. 普通画布和短剧之前只更新顶层混合素材引用，嵌套分组中的 URI 没有跟随连线素材替换／删除。两页在覆盖旧引用前，统一调用共享分组协调逻辑，以字段和独立槽位更新声明中的 URI；同文件另一字段的用途、说明及 false／0 保留，不按 URL 抢占其他用途。沿用已有歧义处理，不猜测同一字段复杂多用途的替换目标。
3. 正常页面追加发现：短剧素材替换发出的是 url／uri 等源节点补丁，未触发下游协调，保存的缓存引用仍旧。现在完整素材变更会刷新下游，上传中的瞬态补丁先保留旧分组，成功或回退后再处理；这一路径不重新筛掉作者连线。实际页面修复前／后分别读回 SQL 验证，保留[历史复现证据](history-reuse-before-batch-33-20261031.json)。这条复现只证明持久缓存未更新，没有声称当时的动态请求必然错误。

API、迁移、权限、manifest 和状态枚举均未变化。server 负责图片应用共享同步、回滚测试和台账；web 负责共享分组协调、两类画布接入及实际页面触发修复。

## 普通画布与短剧

[隔离分组浏览器证据](canvas-grouped-media-batch-33-20261031.json)使用实际生产节点组件、共享素材组件和从两页提取的实际协调函数，通过 HTTP 到真实只读准备层；两组分别绑定图片／视频／音频，复用同一文件但保留不同字段和槽位。两入口的旧 JSON 与三类素材替换后重开共4项通过，分别删除图片／视频／音频共6项准确拒绝，指出 group_a 的缺失字段。另一组和 false／0 保留。原生哈希从初始 `23b6ce98…` 到替换后 `b14e424a…`，两入口一致。这是合成声明隔离验证，不能当作正常登录的已发布分组型号、SKU、供应商上传或完整生命周期认证。

[正常 HTTP 全页面](canvas-normal-http-reuse-batch-33-20261031.json)另外覆盖既有隔离合成普通画布和短剧项目：

- 普通画布：把合成图片替换为蓝图，下游图片 URI 更新，视频和音频保留；移除音频当前引用后下游为1图／1视频／0音频，4节点／3连线保留；两次撤销后保存数据与原节点、连线相同，页面重开显示4节点／3引用。
- 短剧：修复前替换复现缓存未刷新；撤销后加载最终源码重测，下游 URI 与新源图一致，视频／音频用途保持。删除合成音频节点后为3节点／2连线／无音频引用。两次撤销、保存、重开后恢复4节点／3连线／三类引用；16:9、1080P、5秒、音频关闭保留，只读页面报价635积分。

共3次合成本地图片上传（普通画布1次，短剧复现及重测各1次），走正常存储，不调用供应商资产接口；保留这些合成上传文件，没有清理用户素材。两个项目的最终业务节点及连线与本批开始相同，短剧服务端内容版本号按实际编辑前进，不回写旧版本。没有点击生成。两类项目新增的嵌套分组 SQL 保存／读取／所有权和版本冲突回归也通过完整事务回滚。
