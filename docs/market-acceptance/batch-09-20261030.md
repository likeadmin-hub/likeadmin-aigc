# 批次 09：关键帧、多主体与嵌套文本

修复了两个共享问题：主体名称/描述中的普通网址文本被误当素材清理，必填描述从实际请求中消失；已编码 `loop_url` 循环帧没有进入共享图片计数。未增加逐型号或逐工具分支。

## 修复及约束

前端按照声明的 URI 类型和既有 URL/URI 字段识别素材地址。上传绑定与移除后的素材投影共用同一识别函数；普通名称、描述和备注保留原值，也不会因恰好等于上传地址就把无关上传文件绑定到主体。对象数组中未标 format 的标准 url 字段继续支持，例如关键帧的 url；数组中的重复 URI 也继续保留。服务端仍执行类型、数量、素材用途、SKU 与保留检查。

后端为已有循环帧字段补图片类型计数，实际素材槽、计量上下文和报价快照保持一致。历史冻结上下文不重算。Grok 本次 SKU 按输出时长计价，不能从计数遗漏直接推断已有任务曾经少扣费；带参考图片附加计量的合成合同回归单独验证新上下文与旧冻结上下文。

路由、迁移、权限、后台能力来源、计价公式和原生合同文件没有变化；既有任务、市场价格及上架配置没有修改，没有市场同步。
