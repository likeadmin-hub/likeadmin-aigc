# 批次 04：默认值、规格协商与报价一致性

## 共享参数投影修复

批次 03 的两个 image_edit 场景中，控件显示 BALANCED，但没有设置参数时请求不包含该默认值，后台按首个可用 SKU 锁定为其他档位。现在共享 `generationParameterPayload()` 在原生模式中，将**已声明、经过类型/枚举/边界检查、且参与多 SKU 锁定选择的标量默认值**带入 `provider_params`。这样，报价和提交准备收到面板实际展示的业务选择，再由后端已有规格协商、材料与计价校验处理。

自动默认值不写入保存的用户高级参数，面板仍显示“使用模型默认值”；明确选择 SKU 时使用该 SKU 的锁定默认值，用户显式设置继续覆盖自动值，重置回正式默认。false 和 0 保持类型，示例不充当默认；不自动发送未影响 SKU 的其他默认值，不新增客户端价格来源。基础控件拥有的参数继续排除；旧无原生模式调用路径保留。

这不是隐藏错误提示，也没有模型名或工具分支。只修改 web 共享参数函数及回归，源码 `41f7d59a`。后端业务接口和准备器继续校验同一请求，数据库、价格、上架、后台能力来源和旧冻结任务均未改变。直接不采用该共享投影的请求仍按原 SKU 规则处理，不能据此宣称所有工具和协议的默认策略已验收。

## 共享影响范围和回归

对当前 121 个图像/视频目录选项的原生模式做纯投影影响审查，记录了 22 项在“未绑定 SKU、未指定基础控件所有权”的条件下可能输出定价默认字段的模式。这是**影响上界**：实际页面会排除由基础控件拥有的字段，不能说 22 项都实际改变了页面，或均完成报价验收。记录涉及 size、model_version、rendering_speed、audio、generate_audio_switch、mode；其余模式仍待有针对性的参数/素材验证。

对三个受影响的文生视频场景额外构造真实前端投影：Kling 3.0 Omni / SKU 783 的 audio=false，PixVerse V6 / SKU 742 与 V6 Max / SKU 472 的 generate_audio_switch=false。只读调用实际视频 estimate 和冻结快照准备，三项均保持 false。它不覆盖其余视频模式或实际页面。

- 227 项 PC 回归通过，含共享高级参数、上传、报价、首页/创作页、画布、短剧和图片批次的相关用例；另 7 项历史请求重建回归通过。
- 新增 3 项针对性测试覆盖自动默认不会成为用户覆盖、显式 SKU 与显式值/重置的不同含义、false/0、示例和旧协议不被自动提升。模型定义和 metadata 不被改写。
- 历史再次生成从历史详情重建请求，重试批次使用已冻结的请求槽位，不从当前可编辑表单重建；本批未回写现有任务。后端源码未变，没有把此前 773 项后端测试冒认为本批新跑。
- 所有执行在对应本地 develop，源实现提交在 feature；代理、skip-worktree、构建产物保留，仅交付源码。
