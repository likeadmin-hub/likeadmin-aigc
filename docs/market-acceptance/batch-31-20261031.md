# 批次31：旧任务重开、冻结规格与混合独立用途

本批补三类旧终态视频任务的正常登录历史重开与只读冻结回放，并推进结构化混合素材和同文件独立用途。发现并修复历史编辑恢复丢失声明输入的问题；没有收费生成、供应商任务创建／重试或资产调用，没有手工改写原项目或原任务；初轮HTTP历史读取触发的自动时间字段更新已定位并修复。整体软件适配仍未全部完成。

## 修复与共享影响

[修复前的合成重放](history-restore-before-batch-31-20261031.json)显示，历史请求恢复只将provider_params浅拷贝进普通参数，未恢复嵌套路径、主体素材和显式素材方案。共享准备因此漏掉音频false、seed=0及主体输入。这是实际恢复／准备函数的可复现缺口，不能冒认为三份既有任务都发生过同一问题。

web新增共享声明恢复投影：依据精确型号和已选素材方案，将显式保存的嵌套控制和结构化素材恢复到各自存储，保留false／0、缺省／null／空值区别，不写入新目录默认。现代创建页将当前型号声明交给恢复层；新编辑报价仍依据当前目录，旧任务执行快照仍独立冻结。引用的页面ID与用途槽位分离，旧槽位跨字段复用也不会造成页面ID重复。历史请求本身保持不变。

结束盘点又发现历史列表会调用终态回填：视频服务每次无条件写update_time，失败结果还重设finish_time。初轮页面访问后44条终态任务行哈希发生变化，这些访问不计为“原任务未变”。现仅在上游编号、状态或错误等实际事实变化时保存，已有失败完成时间保持；延迟失败和迟到编号仍可补齐。未按猜测手工恢复原时间。最终修复后，新开正常HTTP页面、三类历史重开及重载前后，44条任务完整行哈希全部相同。详见[历史复现](history-terminal-reconcile-before-batch-31-20261031.json)和[最终HTTP核对](history-terminal-reconcile-http-batch-31-20261031.json)。

正常页面还发现灵感卡片租户编号字符串与Number属性不符的Vue告警，调用处做数值转换。未改租户解析、鉴权或权限。最终正常新页面无错误／警告。

## 旧冻结规格与更多混合字段

[旧任务冻结回放](history-frozen-replay-batch-31-20261031.json)在强制只读SQL事务内读取上述终态任务，按持久业务字段重建输入，使用其pricing_snapshot准备并JSON重开再准备。product98/SKU119、product94/SKU104、product357/SKU808的原生输入和计量上下文分别保持相同，只读事务内原任务行哈希不变（不代表初轮HTTP读取没有自动更新）；槽位分别为2图、图视频音频各1、1图。

product357旧快照的音频默认true保持；只将内存中的声明副本default_params.audio改成false，新副本采用false，原冻结仍为true。没有改真实目录、价格、SKU或任务。两个更老快照没有market_metadata／billing_meter，本批只认证当前代码对它们的有限重建一致性，不能据此补足旧完整合同、现代计量或历史供应商原始请求。

新增PHP合成合同覆盖图／视频／音频各自source／style六个独立字段：同URI跨字段不合并，冻结重开保留每个字段和false／0，删除一个必填用途不能借另一个字段补位，单字段超上限拒绝。这是声明能力边界测试，不向任何真实资源扩散通过结论。
