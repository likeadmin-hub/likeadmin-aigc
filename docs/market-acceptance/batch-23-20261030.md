# 批次23：结构化主体文件联动与字段感知的视频模式

本批修复主体文件替换/移除与结构值脱节、模式及节点可用性丢失字段绑定、把上传文件数当作主体数的问题。**整体模型/应用适配仍未全部完成，没有新增收费生成。**

## 复现与共享修复

1. 使用当前Kling 3.0声明及实际共享素材面板复现：同一上传使用ID替换成新图片后，主体结构仍保存旧URI，参数投影将其过滤，主体图片数从1变0。本批共享面板在上传/失败恢复结束后，按使用槽/ID和字段更新声明中的URI；移除文件时删除对应URI，保留主体行、名称、描述、false、0及其他模型配置。普通文本中出现的网址不被当素材改写，文件/网页专用来源不被当上传引用清理。
2. 相同地址有多个独立用途而无法唯一对应时，不把整个分组替换掉；显示重新指定或恢复默认提示。无稳定使用身份的旧引用不猜测替换关系，缺失素材继续交给合同拒绝。没有新增默认主体、伪造必填值或扩展合同能力。普通用户的可选主体继续默认省略，历史自定义主体沿用已有提示/恢复默认入口。
3. 有限交叉检查还复现：画布只按媒体数量判断，会将仅属于主体分组的图片误当普通首帧/双帧。现在归一化和模式协调传入实际素材字段、角色和使用槽，复用共享完整模式选择；保持不完整双帧编辑、无兼容组合保留输入、合法替代模式迁移。两个节点也共用保留身份的实际素材摘要与原生校验，不再丢字段后判断可用性；旧URL别名仍合并、独立使用保留，blob待上传状态继续阻止使用。
4. 一个主体内多张图片曾按多份主体比较上限。现在未提供明确结构值时，只能按声明的媒体预算限制暂存文件；提供结构值后仍按实际主体数量检查上限，完整嵌套类型/条件/必填/计价由既有准备边界校验。不放松最终合同，也不把暂存允许当作可生成。
