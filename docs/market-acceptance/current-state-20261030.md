## 证据如何合并

[当前机器索引](current-acceptance-20261030.json)由仓库内 `scripts/reconcile_market_acceptance.py` 对前26批36份机器证据构建，保留来源文件、SHA256和JSON指针、原始状态、精确身份、SKU、素材方式、入口和参数场景。初始[8320入口单元](tenant-1-baseline-20261030.json)不覆写；新场景形成独立键，同键的报价/提交、旧版本及失败复现证据全部保留。

本次有1380条满足六个维度的观察，形成942个唯一场景键；1897条缺少至少一个精确维度的记录另列 `unbound_observations`，不按名称猜身份、不把一入口扩散到其他入口、不用某SKU替代全模型。逐资源清单同时链接两类记录，已有证据不会消失。

绑定观察内1322条为限定检查通过、11条为预期拒绝、40条为外部阻塞、7条尚需按原始范围复核。**这不是当前故障数、生成成功数或全量完成率**：同场景存在多次记录，旧失败也可能已由后批修复。只完成字段展示、报价、构造或冻结回放的证据不升级为上传、生命周期、历史任务或完整入口通过。没有完整七维检查点证据的入口仍未结案，不能据此说之前的工作没有效果。

可在两仓库最新feature已合入本地develop后，从server执行：

```sh
python3 scripts/reconcile_market_acceptance.py --output /tmp/market-current-acceptance.json
python3 -m unittest discover -s scripts/tests -v
```

状态枚举保留通过、预期拒绝、失败、未覆盖、不适用、外部阻塞。不适用需要人工记录理由，导入器不会自动生成。没有足够语义的旧 `quoted`、泛化 `passed`、未注明预期的拒绝先保留待复核，不能为了显示通过率而推断。
