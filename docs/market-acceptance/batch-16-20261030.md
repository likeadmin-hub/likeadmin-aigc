# 批次 16：应用多图、多帧、音视频组合与入口回归

本批按用户优先顺序，先核对应用复杂素材，再完成受影响入口回归。修复了实际复现的短剧引用丢失，新增逐资源有限准备证据与实际 PC 上传观察。**整体软件适配仍未全部完成，供应商生成未追加实测。**

证据：[70 项应用准备与有限页面观察](application-materials-batch-16-20261030.json)。每项绑定精确选项/app/api、SKU（报价成功时）、生成方式、素材数量、入口和场景；没有把测试总数当作完整矩阵通过数。

## 已复现与修复的共享问题

1. 原短剧 runPayload 会删除 reference_slot_id、field、parameters 与部分持久地址；同文件两个显式引用只输出一份。离线复现输入 2 份视频使用槽，输出 1 份且槽位标识为空。
2. 后端 mergeReferenceAssets 仅按类型/asset_id/role 去重。两个没有 asset_id、地址不同的图片会合成一份；同 asset_id 的两个显式使用槽也会合成一份。两项实际反射调用均复现 2 → 1。
3. 现在在共享素材帮助层区分存储身份、字段/角色和独立使用槽；同一选择器与图连接的旧别名仍合并，图记录可以补充所有权/存储信息。不同文件、不同显式槽、不同绑定及首尾帧保持，冲突槽位不允许换成另一文件。
4. 短剧复用既有 videoReferences 投影首尾帧、普通参考及原生字段绑定，面板元数据和估价/提交共同使用；不再在工具内单独重写角色。容量预检计入显式使用槽/字段，保留 blob 预览对应的持久地址；原节点数据不被改写。
5. 不新增逐型号分支，不改供应商协议、计价公式、后台能力来源或能力表。CanvasNodeReference 的可选槽位/绑定字段只是保留原本已经支持的请求信息；没有新路由、迁移、权限或 manifest 变化。

修复后相同复现的输入 2 份均保留 2 份。相同 URL 的首尾帧仍是两个角色，重复的同一槽位仍只计一次；素材、SKU 和计价校验未放宽。

## 实际浏览器观察

在含最新 feature 的本地 develop、当前已连接租户账户中，经正常 SaaS 上传入口上传三张不同色块 PNG、合成纯色视频和测试音频。没有点击生成或调用供应商资产注册/上传。测试页已关闭，既有用户页和预览进程保留。

- PC 图像：精确选择 **Nano Banana 2 Official 应用 API**（不同于同名图片模型），实际三图上传后切到参考图模式；1:1、1 张，2K 显示 40.91，改 4K 为 48.64，三图保留。按可见 4K 选择重建的生产投影准备得到 SKU 151 / 48.64。
- PC 视频：**full_video/submit 全能视频应用**，两图+一视频+一音频全部上传完成；4K、1:1、5 秒，视频编辑与全能参考往返，四份素材保留，显示 200。对应有限生产投影准备得到 SKU 131 / 200。
- 移除视频和音频后两图仍在，切首尾帧 tab 两图分别作为首尾帧，显示 200；切参考素材后再实际上传第三张图，选择多帧参考，三图均保留，仍显示 200。对应两项有限生产投影的 SKU 131 / 200 一致。
- 两个 tab 沿用用户最终规则：有首尾帧能力的资源均显示，混合音视频或三图不能直接切首尾帧时给出调整素材提示。首尾帧区域只用于首尾帧；其他模式使用参考素材。

浏览器中看到的是实际上传、可见选择、模式、素材和报价；**没有直接抓取浏览器发出的请求 DTO**。五项可见选择用实际生产函数重建后作只读准备，证据明确区分这一边界，不能据此冒认已完成 wire DTO 抓包或全入口整页验收。
