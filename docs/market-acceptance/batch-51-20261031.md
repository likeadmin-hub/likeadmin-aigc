## 本批具体完成

1. **修复有效图片转存的参数类型错误**：共享结果服务把存储配置传到图片服务的第四个布尔参数，合成有效 PNG 在上传前即抛 TypeError。图片存储保留原有安全下载／像素上限参数，在第六个可选参数接收存储配置，贯穿内嵌图片、远程图片和上传流程；回执域名由实际使用的配置计算。结果 worker 调用开启图片字节核验，未完成有效转存不得标为 stored。
2. **修复按应用运行的 worker 看不到转存任务**：转存入队从资产读取所属 consumption 和应用任务，继续使用既有 `transfer_result:<assetId>` 幂等键。再次入队可补回旧 pending 任务缺失的关联；未对真实旧队列执行批量修复。重复入队保留未到期 running 转存的租约，避免把正在执行的转存重置为 pending。
3. **修复转存完成后业务结果仍引用原始地址**：已存资产按 consumption、租户、用户及原始／本地 URI 核对后，投影到标准 images／videos／items 的 URI 与存储信息；图片业务结果继续保留该信息。原始地址保留在资产行，费用快照和原始其他回执字段不改。重复收集也能由本地 URI 找回同一资产；已存资产重试可恢复业务回填。视频／音频仅验证标准摘要投影，不宣称实际视频／音频文件转存已验收。
4. **完成有效图片本地落盘与归属验证**：真实存储驱动将 1×1 合成 PNG 写入私有临时 public 根，核对字节 SHA256、实测尺寸、存储范围、引擎及文件归属行。显式 tenant/local 配置与无效字节拒绝也通过；5 个 PHPUnit 场景的数据库写入完整回滚，临时文件清理。
5. **完成实际结果 worker 进程中断恢复**：专用随机 SQL 前缀复制空表结构，使用私有文件／缓存根、假租户和假用户，不接触真实钱包。启动生产 `AiTaskWorker` 命令，按应用领取转存后、处理前 SIGKILL 自己的子进程；重启先保持未过期租约，等待自然到期后接管，写入一份有效文件及图片业务结果。第三个进程再次启动后终态队列与文件数保持不变。旧 pending 关联修复、活租约不被重复入队夺取、业务 URI／存储回执相同均有断言。最终 0 个隔离表、0 个私有根和0个本批 worker 残留；原有常驻 worker 保留运行。
6. **完成两份隔离项目正常登录 HTTP 保存与重开**：通过正常账户页面新建普通画布890、短剧531，明确标记批次51。把 worker 导出的合成 PNG 经正常上传入口用于两图；短剧另有32×32合成色块。普通画布2节点／1边，短剧4节点／2边，目标均为 FLUX 3 Klein。关闭标签后通过原正常 HTTP 地址新开，节点、边和视口完整相同，素材能加载，提示词恢复；短剧重开后仍显示1:1／2k及10点估价。两图运行记录均为0，账户页面积分始终4,372.96。截图使用正常缩放控件调整至50%，不把截图后的视口变化算作恢复漂移。

正常 HTTP 上传使用现有 tenant/aliyun 存储，三条上传回执的租户／用户归属匹配。它证明正常上传、保存与加载，不替代结果 worker 的云端转存测试。worker 使用独立前缀的合成终态回执，输出再通过正常页面上传；**这两段没有伪称为同一条 HTTP 生成任务的端到端执行**，没有注入登录身份或修改真实生成任务。
