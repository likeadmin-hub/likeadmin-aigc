# 批次 03：多组素材标签、模型切换与默认档位缺口

## 已交付的两个共享修复

PC 实际复现：Ideogram Character 的图片编辑模式，主图和角色参考图两个必填用途都显示为“参考图片”。`generationMaterialLabel()` 原来没有接收当前模式 metadata，读取的是默认模式字段；其他模式的字段标签丢失，落入同一回退标签。现在面板按实际选中模式读取标签；同名图片组增加稳定组号和该字段声明上限，区分单张输入与额外图片组。参考遮罩保留“参考图遮罩”的语义；无法得到安全中文标签时使用通用素材标签，不显示协议字段名。没有按型号名称判断。

另一个实际复现：将已明确分配主图、角色图、参考遮罩的 Character 切到 Qwen Image 2.1，旧 `field` 仍保存在上传 DTO 中，新模型无法正确识别模式，三份素材仍在但只显示“参数待调整”，用途面板也不可用。共享组件现在监听模型身份变化，仅移除新模型所有模式均无法使用的字段绑定，保留 URI、顺序、重复槽、类型、角色和仍兼容的绑定；不会静默删除不支持的素材。随后让新模型合同分配和校验，不绕过条件、数量或计价规则。

涉及 `web/pc/components/ai-generation/` 的公共参数函数及素材面板，创作页、首页和画布兼容导入共用。源码分别为 `7583f5aa`、`7e3e2502`。后端业务源码未改变；没有 API、迁移、权限、manifest、任务状态或后台能力来源变化。

## 数量语义与准备检查

PC 的 1–4 张选择是多个输出槽。`estimateImageSlots()` 使用每槽 quantity=1 的报价后聚合，批次提交亦每槽 quantity=1；这不等同于向某个仅支持 quantity=1 的通道直接发送 quantity=2。检查时不能把两者混用，也不能为了测试通过放宽通道数量限制。本批未创建批次、预占或上游任务。

本地只读事务用明确的请求字段构造 6 项估价，将 quote 的冻结 market_snapshot 与当前 selectionSnapshot 交给实际 `prepareRequest()` 比较原生输入；核对单槽金额、SKU 和槽聚合价格相符，并保留图片/遮罩各组数量。另 1 项“两张输入图 + 遮罩”按预期拒绝。未输出原生完整请求或素材 URI。

这些是显式档位的后端准备观察，**不代表自动默认档位已经正确**。精确身份、SKU、模式、材料计数、状态和缺口见 [增量 JSON](pc-image-groups-batch-03-20261030.json)，其声明指纹来自初始目录观察，不是新取得的平台完整合同。

## 新发现的未通过项：渲染速度默认提示

| 精确目录选项 / 模式 | 公开默认提示 | 无显式档位的后端准备结果 |
| --- | --- | --- |
| Character，产品 274 / image_edit | BALANCED | SKU 377，QUALITY，96 / 槽 |
| Ideogram V3，产品 273 / image_edit | BALANCED | SKU 370，TURBO，14 / 槽 |

这个差异在本批只读检查中被保留为 `open_default_display_mismatch`，没有通过改测试预期掩盖。面板在编辑模式没有基础比例/清晰度行时缺少当前 SKU，沿用参数声明的 BALANCED 默认提示；运行时按当前可用 SKU 顺序选出锁定档位。显式 BALANCED 请求仍能协商对应规格，但“未设置”的展示与准备实际值不一致。

因此，批次 02 的 Ideogram V3 默认 14 报价只能说明当时选出了某个规格，不能说它使用了 BALANCED。此问题不是新拿到的上游行为证据，也不能由当前本地合同匹配得出供应商全量正常结论。

下一批优先对齐公共控件默认值、实际报价 SKU、请求准备和冻结快照的同一来源；评估当前报价 SKU 的显示绑定与合同默认参与规格选择的边界，保护显式选项和历史冻结请求，避免客户端状态与报价互相触发循环。不得给两个型号写特例、仅隐藏默认提示或擅改价格。继续剩余图像参数边界、应用选项及 PC 视频，不在外部资料缺口上空转。
