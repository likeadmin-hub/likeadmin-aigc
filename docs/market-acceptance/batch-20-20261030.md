## 复现与修复

1. [修复前记录](canvas-video-before-batch-20-20261030.json)：Kling 3.0 选择标准无声，画布仍提交派生 SKU646，后端按已有锁定校验拒绝。现在兼容基础维度内复用 `generationPreferredSku`，声音、档位、原生素材方案共同选规格；恢复默认不沿用旧派生 SKU。直接传入的合法显式 SKU 仍保留，不改变共享显式选择语义。
2. 视频画布复用 `generationChoiceValues` 和当前上传/图连线素材上下文，限制比例、清晰度和时长；无维度时清除旧别名。面板、选择及请求共用素材收集，不逐型号增加工具分支；既有 Grok/旧 Seedance 兼容条件本批未新增或扩写更多型号分支。
3. 同一文件用作首尾帧原先按 URL 合成一张，手动首尾帧会改成全能参考；应用兼容路径还会将两项都改为首帧并拒绝。现复用共享素材合并，保留角色、原生字段、显式使用槽及持久 URI，仍合并无独立身份的旧连线/快照别名；容量按独立使用数校验，超限不截断。
4. 实际浏览器又发现 CanvasNode 仍只显示同文件的一张帧卡片。现卡片与请求排序共用 `orderCanvasFrameReferences`，节点统计保留角色/槽；实际显示双帧，交换、缺帧和旧排序键守卫保留。不能用离线请求成功盖过这次页面故障。
5. 跨入口发现画布 `720P` 与短剧正式值 `720p` 精确匹配失败，短剧回退默认1080p，四对场景报价320/480。共享选择现优先精确匹配，再选择唯一大小写等价值；有歧义不猜，保留零值及正式值类型。最终四对均为720p对应SKU691/693、320。不放开任意枚举或改上游合同。
