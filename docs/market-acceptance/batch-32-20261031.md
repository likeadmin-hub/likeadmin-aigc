# 批次32：旧图片历史、冻结规格与混合分组边界

本批补五份旧图片任务的正常登录历史重开、生产历史请求重建至旧冻结声明的只读准备，以及混合分组用途／必填／移除边界。修复三个实际代码缺口。没有收费生成、供应商任务创建／重试、供应商资产调用、原项目保存或原任务写入；本批没有新项目或正常上传。整体适配仍未全部完成。

## 修复

[历史复现](image-history-before-batch-32-20261031.json)保留各自版本与来源范围，不作为当前故障数。

1. 图片历史未接入共享请求恢复，型号切换的选项监听又把旧任务3:4重置成自适应。现在图片工作记录携带保存的请求，按精确型号身份恢复；恢复期间保护选项，保留空分辨率这一合法值，接入既有共享参数／素材投影。重复显示名不替代精确身份；型号失效显示提示并阻止直接生成。显示图片URL沿用现有规范化，提交URI仍保留原值。
2. 编辑一个结构化分组时，面板会把相同URI在另一字段的独立用途一并抢过来。现在只变更本字段或尚未分配的用途；另一字段的用途和组值保留。对于借用其他字段上传事实的组，最终文件用途被移除后也清除已失效URI，保留名称、说明、false／0和必填行供校验。仍保留同一字段多用途替换的歧义提示，不猜测目标槽位。
3. 旧Nano应用图片记录把variant及market_sku_id保存在provider_params_json，历史重建误当可编辑原生参数传入，旧冻结准备报“图片参数未声明或不可编辑”。现按这一既有存储格式还原到业务请求层；不改其他模型的同名原生字段，不改旧记录或供应商校验。直接再次生成的处理器只用隔离API替身回归，浏览器未点击该按钮。

## 实际共享组件与分组移除

[分组浏览器证据](grouped-media-browser-batch-32-20261031.json)使用生产GenerationMaterialPanel、嵌套参数编辑器和共享请求函数。隔离壳以合成声明展示两个必填组，每组各有图片、视频、音频，两个组复用相同文件URL但用途身份独立；HTTP业务输入交给真实PHP原生／冻结准备，桥接限定合成URI并强制只读。它不是正常应用鉴权／后台接口DTO、真实资源SKU或供应商实测。

- 实际键入并提交分组一名称后，仅该组名称改变，六个用途仍各归原组；两次准备及冻结回放相同。
- 移除分组一音频用途后，仅该组audio_url失效；分组二的同音频及其他素材保持，真实准备因group_a[0].audio_url缺失拒绝。
- 用生产控件删除整组一后，仅其三条用途取消字段分配，分组二保留；真实准备因必填group_a为空拒绝，没有借另一组补位。
- 删除必填名称后，真实准备明确拒绝group_a[0].name。
- 重开旧JSON后，全部组值、六条用途、false／0恢复，原生哈希回到初始值。
- PHP合成合同还覆盖删除必填图、视频、音频、名称、整组以及单组超上限，并断言具体拒绝字段；既有其他组、不同用途及完整回滚生命周期继续回归。
