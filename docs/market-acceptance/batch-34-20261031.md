## 歧义修复

[历史复现](grouped-history-before-batch-34-20261031.json)保留旧版本：共享协调函数虽返回歧义，旧请求层仍可构造携带旧分组的输入；短剧旧连接策略又把合法的主体分组按普通参考图计数，Kling 3.0 的4图／2主体得到0个可选型号。

1. 歧义现在以可选编辑元数据 generationMaterialConflicts 保存，按精确型号、素材方式、字段和有歧义的 URI 分开。再次协调和 JSON／SQL 保存重开不会悄悄放行；其他型号、其他方式及其他字段不受影响。兼容较早的字段数组标记。
2. 两个共享请求边界和参数错误检查均先拦截未解决的歧义，短剧生成输入检查也接入同一错误。标记不作为供应商控制或素材参数传出。仅改名称／说明不会解除；同字段两个 URI 有歧义时，修复一个仍保留另一个。
3. 画布属性与短剧参数面板在有歧义时显示实际分组修复表单，并提供当前素材选择；图上的素材仍由图管理。明确重选对应 URI 后解除该处标记，另一组保持；恢复默认会清除相应组和标记并保留素材。没有歧义时继续使用既有摘要布局。
4. 短剧的已声明素材方式使用共享能力判断，不再用旧平面图数筛掉合法主体模型；同时保留分组行数、必填、类型和歧义的提交校验。连线来源按 sourceId／独立槽位协调，同文件的不同用途不合并。未声明的旧模型仍走原兼容逻辑。

没有 API、权限、manifest、数据库列或状态枚举改动；新增的是既有节点 JSON 内可选的编辑门禁状态。旧图没有该字段时沿用既有行为。

这仍是“当前已发布声明＋实际组件／页面函数＋真实只读准备”的隔离验证，不是正常登录下已发布分组项目的完整 E2E，也不是供应商资产或任务生命周期认证。其他主体资源、角色ID接口、SKU、素材方式与所有交叉仍保留未覆盖。

隔离壳初期缺少 Nuxt 自动组件注册、短剧 native string-ID 适配及足够的节点布局空间；修正后执行最终交叉。壳内同时挂载两份共享表单造成字段ID重复，用明确 DOM 作用域验证修复表单；不把这些壳问题记为生产回归。默认恢复曾点到被覆盖区域，增加壳间距后四组重新核对通过。临时诊断与准备接口没有进入产品源码。
