# 批次29：项目事务保存重开与帧用途投影

本批继续普通画布、短剧的连线与素材复用交叉，补真实服务／SQL的保存和重开证据，并修复缓存用途、角色与实时来源之间的不一致。整体适配仍未全部完成；没有收费生成、供应商调用或用户原项目写入。

## 复现与修复

[历史复现](canvas-persistence-before-batch-29-20261031.json)保留旧源码夹具与中间阶段的范围，不能作为当前故障数。

- 短剧原先按数组位置改写首尾帧。保存的尾帧在前、首帧在后时，重新协调会颠倒用户已指定的角色。现在保留显式帧角色、原生字段和独立用途槽位；仅无明确角色的旧引用按方式补默认角色。
- 普通画布原先把保存的来源引用和当前连线别名重复计算；首尾帧两用途可能被视为四张图而拒绝。现在在请求边界按实时图来源协调缓存，连接断开后缓存不会复活；替换来源只更新该用途的文件，保留其字段、角色和槽位。
- 普通画布排序、素材数量和旧 `reference_images` 别名从已协调用途派生，显式首尾帧顺序保持一致，字段绑定用途不会被别名重复计算。短剧 composer 与两个节点的方式能力检查也使用共享用途声明。
- 同一文件的两份独立用途、手动显式槽位、蒙版和不同原生字段继续独立。旧文件资产／存储／尺寸等事实不能跟随替换；当前来源带来的新资产标识和存储事实会完整保留。受影响的既有测试曾发现去重后丢失 `asset_id=71`，已修复并通过回归。
- 源码复核还发现旧字符串URL列表在协调时被过滤。共享边界现兼容字符串引用，普通请求与短剧协调均有真实函数回归；普通首帧排序从已解析用途读取。
- 后端新增测试，无业务实现修改；没有新增API、权限、迁移、计价公式或市场声明。复用既有引用、资产身份和项目版本字段。

## 页面和真实事务服务

[浏览器DTO与事务记录](canvas-persistence-browser-wire-batch-29-20261031.json)来自临时本地页面的真实 `CanvasNode`／`ShortDramaCanvasNode`、生产请求／协调函数以及实际 `Canvas`／`Drama` 服务与SQL。项目与资产元数据均为新建合成夹具，放在完整外层事务中，最终回滚；没有注入登录身份、修改用户原图或原任务。

| 场景 | 普通画布／短剧有限验证结果 |
| --- | --- |
| 尾帧先、首帧后，两来源绑定独立用途 | `tail-use`保持尾帧，`head-use`保持首帧；H3 product98、768P／16:9／5秒，SKU119／250点；原生图片数2 |
| 真实服务保存、SQL重读、重建组件 | 用途与角色不变，估价／准入／原生／冻结回放一致；两入口初始准备hash相同 |
| 用合成蓝图替换尾帧，再保存／重开 | 只改变尾帧素材；首帧／槽位／型号／规格保持；两入口准备hash相同且区别于替换前 |
| 用上一版本尝试保存 | 普通画布返回其他窗口已更新，短剧返回VERSION_CONFLICT；当前图及准备结果保持 |
| 结束外层事务 | 普通图、短剧图与新增资产元数据剩余记录均为0 |

最终捕获15份估价DTO：13份列明边界一致，2份预期拒绝；包括重复读取／旧保存拒绝后的重复估价，不等于15个唯一资源场景。短剧未保存目标节点时拒绝NODE_NOT_FOUND；新尾帧资产已换、权威图尚未保存时仍拒绝不一致帧对，保存后才通过。拒绝不升级为生成成功。

短剧使用实际 `Drama::quote` 和已保存图的资产归属解析，再核对视频估价／准入和冻结准备；没有使用canvas_id=0跳过图所有权。源替换按钮由夹具提供同事务中新资产事实，没有调用实际上传控件或供应商资产接口。素材沿用此前正常上传的合成色块及其真实OSS存储元数据。初期把OSS误标本地存储、替换时保留旧资产ID的夹具尝试均已回滚并排除，未据此修改生产代码或认定产品故障。

边界：这里认证真实服务和SQL的**事务内**保存／读取，不认证正常登录HTTP保存、提交事务后持久化、进程重启恢复或真实用户项目。混合视频／音频和同文件首尾帧的SQL保留由后端合成合同测试另证，不冒认本页H3支持混合素材。临时包装页缺Nuxt的ModelSourceBadge自动注册，有组件解析警告；不声称该轮控制台零警告。
