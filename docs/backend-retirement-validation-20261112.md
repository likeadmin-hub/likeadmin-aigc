## 执行安全与退役

新增工具默认只审计。应用处理要求清单 SHA256、操作人、原因及明确核销批准，并拒绝非本地数据库、其他应用、价格或消费状态已变化、有预扣、实际金额或资金流水的记录。整个批次在同一事务中处理；过期清单导致整批回滚。

先在一次性数据库演练核销、重复执行、备份与退役，再按用户批准应用到 `z_cn`。实际回读发现旧 PHP 微视频进程仍持有升级前代码，曾继续刷新作业 140，并在消费关闭后将其置为解析错误。已：

1. 备份原守护配置和旧进程造成的作业改动。
2. 仅停止 `aigc-micro-video`，将其 autostart/autorestart 改为 false；不重启其他应用。
3. 锁定并逐字段核对作业 140，确认业务内容及回执未变后，仅恢复其四个状态/调度字段到退役备份。
4. 再次核验 **13 张历史表完整摘要、所有租户/用户余额、资金流水及全部微视频消费原始证据均与处理前一致**，数分钟后再次回读仍一致。

增加 `RetiredAppWorkerGuard`：收尾和退役脚本执行前检查本项目旧微视频 daemon。真实无业务子进程验证能阻断活动 worker，同时不会匹配其他项目。正式操作顺序应为：停用旧 worker → 私有备份 → 审核证据和资金决定 → 核对收尾 → 退役 → 独立回读。
