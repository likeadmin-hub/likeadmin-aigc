# OEM 自助贴牌 v2 运维说明

## 启用与兼容

由系统升级器或迁移执行器按顺序执行 `20261013_oem_self_service_v2.sql`、`20261013_oem_self_service_v2_operations.sql`、`20261014_oem_maintenance.sql`、`20261014_oem_payment_reconcile.sql`、`20261014_oem_refund_recovery.sql`；全新安装 SQL 已包含这五项。重复执行保留定价、销售资格和任务配置。平台默认三档草稿套餐，配置价格与应用权益后启用，销售租户配置零售价并上架。

平台“贴牌业务”设置销售资格与新版入口。入口关闭只阻止新申请；现有付款、采购、退款、审核和开通任务继续处理。历史订单保持 v1，在原套餐订单页查询。新交付租户无继续销售 OEM 的资格。

平台“租户管理 → 租户列表”也提供“贴牌授权”行内开关，沿用 `brand.order/saveSeller` 管理权限。开启会同时授予销售资格、开放新版申请；关闭停止新增采购和申请，已经付款的客户订单仍能按原流程采购、审核和开通。需要只暂停客户申请而保留销售资格时，继续在贴牌业务的销售资格设置中分别调整。授权本身不会赠送额度，租户仍须采购并由平台确认收款后入库。

若 PC 配置接口出现 `oem_flow_enabled` 缺字段，说明数据库尚未执行上述 OEM 迁移。备份并确认当前环境后，按顺序通过 `SqlMigrationExecutor::execute` 执行整组迁移，不要只手工补这一列。执行器会忽略已存在的新增字段/索引；重复执行不重置销售资格、套餐定价、历史订单和已购买额度。两份升级 SQL 与新安装 SQL 已包含完整结构，无需增加重复迁移。完成后复查 PC 配置、租户列表、贴牌目录与销售资格读写接口。

## 执行与守护

OEM 单独运行 `php think brand:worker`，站点数据库锁确保并发为 1。主启动组 `scripts/start-ai-task-worker.sh` 已包含独立 OEM 子进程；仅当站点没有使用该组时，才单独守护 `scripts/start-brand-worker.sh`。不要同时配置两种启动方式。SIGTERM 排空当前任务；运行版本变化后保留步骤并退出，由进程守护启动新版本。数据库连接失效时退出，不重放 SQL。

`brand:maintain` 每分钟由原计划任务系统调度，处理有限批次的付款/退款核对、未付款 30 分钟关闭和付款超过 24 小时的每日跟进提醒。提醒记录保存在订单时间线和后台统计中，由人工跟进；不会自动退款。长时间开通只由独立执行器完成。

## 付款与退款

客户使用销售租户收款配置，采购使用平台配置。回调和服务器查询核验交易、金额、币种及原商户。关闭订单的迟到付款和重复交易按交易记录全额原路退款，不复活申请。

付款仅进入审核。租户完成审核和额度冻结才能提交平台，平台确认后创建任务。技术重试沿用原任务、原目标租户、原冻结记录。

开通前拒绝自动安排退款；客户主动申请由租户审核。已有开通执行记录时，暂停任务，由平台核对执行已停止、部分新租户未激活、没有已交付合同/应用权益后才能同意退款。结果不明先查询原退款单，重试保持同一退款编号。原商户变更、凭据不匹配或渠道失败进入人工处理；平台恢复原配置后使用“核对并重试退款”。不提供手动标记付款或退款成功接口。

只有渠道查询确认成功才更新退款完成并释放冻结额度。多付款交易的退款单独处理，不取消正常客户订单。退款异常详情不向客户披露内部错误。

## 交付和域名

新租户交付前禁用；交付核对后短事务授予成交快照权益、消费额度、激活并写入服务到期时间。首次期限从交付成功起算。续费复用原租户，从现有期限与交付时间较晚者延长；不重置品牌、收款配置或正在运行的任务。未到期但被人工暂停的租户需先由平台核对，续费不能解除人工暂停。

品牌 Logo 按订单持久复制，不依赖源素材继续存在。原商业授权版权策略继续生效。新租户不能继承平台模板中的支付商户凭据。

默认 `/t/{id}/admin/login` 登录、`/t/{id}/admin/user/setting` 设置账号。自定义域名交付后在“我的贴牌”生成 TXT 验证记录。域名需指向 `project.http_host` 的公网地址，服务器管理员完成站点绑定与有效 HTTPS 证书。服务端验证 TXT、全部 A/AAAA 公网地址、证书和本站随机挑战响应后才启用别名；不接受内部地址、协议/端口/路径、平台域名及其子域名。检查失败不影响编号地址。

## 验证边界

只使用 `oem_*` 独立数据库及隔离站点。测试模拟外部支付渠道，生产代码无跳过验签、标记付款或模拟渠道入口。真实扣款与真实退款按约定不执行。自动测试和浏览器验收证据以最终测试报告为准，构建完成不能代替站点部署及验收。

微信通知在解密前验证原始报文签名与五分钟时间窗口，平台证书仅从微信官方 HTTPS 接口下载并缓存，不信任租户自行上传的验签证书。平台“退款交易核对”覆盖客户和采购退款异常，按原交易退款记录重试，固定编号先查单；采购正常到账额度不受多付款退款影响。

付款核对不按订单年龄截断，已关闭订单收到迟到款仍进入原路退款。每轮保持有限批次和时间预算，按上次查询时间轮转，专用索引避免全表排序；原收款配置变更后需先恢复原账户，再核对渠道结果。
