## 三端浏览器验收

使用真实 Chrome、生产构建、HTTP 内核、认证与数据库、实际 `brand:worker`/`brand:maintain`。只模拟外部支付渠道，没有拦截伪造业务 API 响应。二维码从浏览器截图像素解码，内容与数据库意图一致；交付后实际登录子租户后台并核对品牌。

1. 有库存：客户扫码付款 → 租户审核和预占 → 提交平台 → 平台确认 → 执行器交付。
2. 无库存：客户支付宝预开窗付款 → 租户审核 → 按单扫码采购 → 查单到账和预占 → 平台确认 → 交付。
3. 拒绝退款：客户付款 → 租户拒绝 → 实际维护命令提交退款 → 模拟渠道确认 → 实际核对后完成退款并释放额度。
4. 失败恢复：付款、审批后注入真实 SQL 故障 → 开通失败 → 平台重试 → 同一订单完成一次交付。
5. 续费：同一子租户、正确到期日、不重建品牌；未付款刷新恢复、关闭停止轮询、取消订单。
6. 支付生命周期：实际查单后 Esc 关闭；重新打开后浏览器返回到缓存页面；均等待超过轮询间隔确认请求停止。取消操作等待实际响应后核对数据库。
7. 移动宽度、减少动画、标题不被导航遮挡；英文/繁体切换；真实匿名 HTTP 域名挑战匹配 Host 返回，其他 Host 拒绝。

最终逐单记录在 `browser/results.json`、`browser/followups.json`、`browser/payment-lifecycle.json`、`browser/locales.json`、`browser/domain-http.json` 和 `evidence/order-ledger.json`；截图与 HTTP 事件同目录保存。最终结果已核对至上述提交，浏览器未捕获 JS 异常；`evidence/source-provenance.json` 核对实际源码字节一致。

最终账本：7 个客户订单、6 笔付款记录、1 笔确认退款、4 个完成开通/续费任务，交付 3 个独立子租户；冻结额度为 0，消费额度为 4。

## 实现选择及代价

- 保留现有前后端工作区和功能分支，用独立克隆/站点/数据库验收，不更新现有业务运行目录。代价：额外隔离副本占用磁盘；最终只保留当前验收副本及证据。
- 按单采购沿用客户成交时的采购报价和权益快照，批量采购使用当前目录版本。代价：以后改变已售订单采购报价需要显式报价/套餐版本规则。
- 超期提醒先保存在时间线/工作台，每日一次人工处理。代价：短信、邮件等外部通知还需单独配置适配器。
- 域名外部传输在自动测试中模拟，并验证真实 HTTP 挑战。代价：实际公网 DNS/HTTPS 部署联调保留在站点上线流程。

## 复现与运维

参见 `docs/oem/OPERATIONS.md`。后端执行 `bash tests/oem-run.sh`、`python3 tests/oem-schema.integration.py`、`python3 tests/oem-faults.integration.py`；三端各目录执行 `node --test tests/*.test.cjs` 和生产构建。

`tests/oem-acceptance-prepare.py` 创建独立 `oem_e2e_*` 测试库和 loopback-only 站点，分别构建三端后按浏览器脚本顺序执行。需要本机 Chrome、Playwright、sharp、jsqr；可通过 `NODE_PATH` 提供依赖，`OEM_QR_MODULE` 指定 jsqr。测试 Docker 镜像为 `likeadmin-install-worker-test:local`，网络 `likeadmin-oem-dev`，仅使用独立 MySQL 容器 `likeadmin-oem-db`。

测试账号口令仅用于隔离站点：平台 `oemplatform`、两个租户端均为 `oemseller`（tenant_id 1/2）、客户 `oemcustomer1` / `oemcustomer2`，口令 `FixturePassword1!`。后台地址 `/platform/login`、`/admin/login?tenant_id=1`；客户端 `/join-opc?tenant_id=1`。默认三个草稿套餐之外，隔离站点另建两档测试套餐，不影响生产默认数据。
