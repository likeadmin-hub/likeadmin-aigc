# 短剧创作可靠性与连续性（生成流程 v3）

## 范围和兼容

- 单集保持一键生成；新任务交给 planning-worker，浏览器只订阅进度。
- 多集保持“故事设定确认 → 分集大纲确认 → 逐集制作”。先生成全剧节奏分配，再按容量拆分大纲；独立 episode-worker 负责正文。
- 新任务在服务端保存 `_generation_version=3`。旧任务没有此字段，不迁移旧结果和素材。已开始任务继续使用保存的版本。
- 无新表、权限或路由；使用现有 planning_unit、plan_version.continuity_json、episode_task.continuity_json。部署仍需既有应用迁移已经完成。
- `episode/start` 的 story_outline_v2 请求必须带 `draft_version`；PC 先 flush 草稿再确认。后台校验版本，保存确认快照，不改写原始模型结果。
- `episode/lists` 增加 needs_review、review_reason、continuity_warnings。已有 retry 接口仅对实际需要复核的成功剧集开放修复；其他成功任务不能重试。租户及用户边界不变。

## 生成和失败边界

1. 区分输入限制、上下文窗口和输出限制，与共享文本运行器的输出上限保持一致；无容量元数据时采用保守配置。估算不是精确 tokenizer，服务端真实用量仍是结算依据。
2. 故事设定不再假设必须容纳三集；完整 JSON、Markdown 包装、常见返回封装可解析，截断或嵌套残片不可冒充完成。
3. 普通单集优先一次生成；长时长或小容量模型使用骨架和按场景镜头块。块失败仅拆分/修复该块，单集主体最多 48 次调用、192000 请求输出 token 预算，额外质检/连续性检查为既有有界步骤。这是处理上限，不是固定费用或全系统金额封顶。
4. 付费返回先保存收据再解析，恢复时重用；同单元上下文变化拒绝复用。仅确认提交前连接失败可延迟重试，不确定读超时不得自动重发。用户主动重试仍可能产生新的费用；收到但无法通过校验的结果保留，调整输入需创建新版本。
5. 单集/故事任务由 planning-worker 持有任务锁；分集由 episode-worker 持有剧集锁。每次提交及最终回写检查当前尝试/取消状态，过期任务不能覆盖新版本。
6. 失败不展示“脚本已生成”的成功清单。后台断线不依赖浏览器续命；上游返回无法恢复时明确失败，不虚构完整剧本。

## 连续性

- 故事设定阶段接收当前目标集数，用于规划主线容量、人物成长、阶段性冲突与可复用场景；默认提示词和租户自定义提示词都携带 `story_scale`。不按集数线性增加主体/场景，不在此阶段生成分集摘要或制作分镜，仍需确认后才拆分大纲。
- 时长未设置时不补默认值；既有时长参数可能来自单集或全剧描述，要求结合用户原文解释，不能直接乘以集数。阶段性主体信息写入已有 `role`、`arc`，场景用途写入 `description`，随已确认设定继承。故事阶段输出预算继续有界，不随 300/500 集扩大为逐集素材清单。
- 已保存设定不自动重写；新生成或在故事阶段发起 AI 修改时应用容量指导。单纯修改草稿集数只更新目标，不会静默触发付费重生成。
- 已确认人物/场景身份、世界规则、全剧节奏、最近两集摘要、累计状态及未回收伏笔构成本集上下文。只移除媒体/运行时字段，不截断硬事实；容量不足明确报错。
- 正文完成后提取状态变化，必须引用真实镜头和原文片段；before 必须与已有状态一致。未知事实不推断；伏笔回收必须有记录。
- 版本保存叙事摘要指纹和前集依赖。媒体/镜头运动改变不会误触发；正文改变会标记本集及后续为待复核，暂停继续自动生成。
- 用户确认复核后生成新版本，原版本和素材保留。模型审校仍可能遗漏语义矛盾；warnings 供人工审阅，不承诺语义绝对一致。

## 回滚

将 `short_drama.generation_version` 设为 0 可停止新任务进入 v3。不要停止已有 v3 任务所需 worker，不删除收据或连续性记录。完全回退源码前先排空或明确取消在途任务；保留用户原版本和素材。共享文本运行器的容量元数据/终止原因变更需同时回归其他文本应用。

仅交付源码，不提交开发代理配置、构建产物或发布包。

# 分镜时长规则

- 新建、生成、修复与编辑保存的分镜统一使用 4–15 秒，缺省 5 秒；实际视频模型的时长档位仍独立校验。
- 普通生成、分段生成、单集/多集、局部修改、时间码拆分、总时长平衡和镜头数估计使用同一规则。时间码超过 15 秒均匀拆分且保留总时长；不足 4 秒的固定片段需用户调整，不能静默拉长。
- 历史配置/任务快照中的旧分镜时长指令在使用时兼容为新规则，并追加系统约束；不改写用户剧本文字、历史素材与数据库已有镜头。新插入行的默认值迁移为 5 秒，迁移可重复执行。
- 回退时需同时回退前后端源码；数据库默认值可恢复为旧值，但不得批量截短已经创作的长镜头。源码回退后旧代码会截短新长镜头，回退前应暂停编辑/生成并评估影响。
