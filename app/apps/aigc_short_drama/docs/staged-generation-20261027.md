# 阶段确认与范围生成（2026-10-27）

## 范围与兼容边界

新界面先确认完整的全剧规划，再到剧集列表核对本次大纲，选择连续集数并明确确认后执行。每次最多 10 集，不能跨当前路线图阶段；当前范围完成且连续性复核通过后，才可确认下一范围。本次没有改为滚动生成局部大纲：仍要求完整分集大纲就绪，沿用前阶段的分批规划与已完成单元恢复。

已开始的旧项目没有 generation_control，继续原有自动生成、取消、重试和制作流程，不自动切换模式。新模式仅显式 opt-in；重复 start 不改写已创建的剧集。原项目、剧本任务、计费记录、镜头、主体、场景、素材和成片不迁移、不清空。展示配置不修改。

## API 与持久化

沿用已声明且需要用户登录的 /app/aigc_short_drama/episode/start，租户、用户、项目所有权校验不变，无新权限、菜单、路由或数据库字段。

- 首次启动：可选 generation_mode=staged；缺省 legacy。故事工作区仍要求原有 task_id / draft_version 等版本校验。
- 范围确认：action=confirm_range、control_revision、confirmation_key（16～80 位字母数字下划线连字符）、range_start、range_end、outlines。范围必须从 confirmed_end+1 开始；outlines 精确包含本次连续集数。
- 仅允许调整尚未开始剧集的 title、story_outline、conflict_point、ending_hook；保留时长、来源边界和其他原字段。禁止覆盖已有子任务或制作项目的剧集。
- 暂停/继续：action=pause_range 或 resume_range，加 control_revision。暂停允许已开始的当前尝试完成，后续集不会启动；失败后的新尝试不自动沿用暂停时的执行许可。继续范围不会自动修复失败集，失败仍需用户操作原重试入口。
- episode/list 新增可空 generation_control；新项目包含 revision、confirmed_end、paused、active、draining、can_confirm、blocked_reason、next_start、max_end、goal、outline、confirmed_ranges。分集增加 awaiting_confirmation。原状态枚举不变。
- 控制数据仅写入第一集 series_json.generation_control，规划编辑叠加于分集 outline_json 与该项目的规划快照，不改写原始已付费任务的请求和结果。
- 未确认的 pending 行使用 next_retry_at=2147483647 排除常规调度扫描，确认本范围时清零。控制信息仍是执行许可的权威来源；该值只用于等待调度，不作为计费或用户进度。

确认事务按项目、剧集顺序加锁；版本冲突拒绝覆盖；相同确认标识与相同内容重复提交成功但不重复入队，不同内容拒绝。首次子项目创建与阶段操作使用同一个项目锁，避免暂停与启动竞争。逐集调度和后续入队均检查已确认范围，原租户隔离、单系列执行锁和计费链路继续生效。

## 前端行为

保留同一版本的未提交编辑，重复轮询不覆盖草稿；确认弹窗取消不发请求。未确认的后续集不显示“排队中”或取消按钮，不触发持续轮询。暂停后仍跟踪已经开始的本集，完成后停止轮询；恢复页面或窗口焦点会刷新状态。失败/复核待处理会阻止确认下一个范围。

## 验证与部署

专项测试覆盖未确认不调度、范围幂等、旧版本冲突、原付费数据与额外字段保留、事务回滚、跳集拒绝、路线图边界、已开始内容保护、暂停当前集完成、租户隔离、旧模式兼容及 500 集分 50 个范围推进；500 集测试为隔离数据库状态模拟，并非 500 次模型生成。浏览器测试使用 mock 业务 API，无真实模型调用。

部署必须先更新后端并重启所有短剧长驻 worker，再启用新版前端。旧 worker 不理解暂停许可，不能混跑；等待时间兼容防线不替代 worker 更新。回滚应先停相关调度并保留数据，回滚到仍支持 generation_control 的版本；不能让不识别阶段控制的旧 worker 执行新模式项目。无需数据迁移或付费重生成。历史项目继续兼容。
