# 分场剧本上下文去重

## 范围与兼容

仅调整后端分场剧本的模型输入，源版本为 1.0.40。新建任务使用输入契约 13；旧任务仍使用原契约及原付费请求签名，恢复和重试不会因本次优化自动重做已有内容。

分场生成中的创作资料由重复转义的 JSON 字符串改为 JSON 对象。完全相同的大对象或数组仅保留一份，其他位置使用本次请求内的 `$ref` 路径引用；每次请求都自带完整资料，不依赖模型会话、其他请求或外部缓存。只比较完整值，不按名称、ID 或相似度合并，不摘要或截断创作资料。

用户原文、修改要求和范围、当前集大纲、权威状态与未收伏笔、当前场景、指定分镜、相邻镜头及场内已完成事实保留直接表示。提示词正文及其顺序保持原样，仅补充当前请求内部引用的读取说明。任一原资料含 `$ref`、自定义模板未提供可信 JSON 标记，或去重后的字节数/字符数不降时，保留完整原请求。

去重发生在原有剧情记忆筛选之后、付费 Provider 调用之前，避免筛选删除引用目标。重新计算输入预算时沿用原有输出上限，不改分段数量、镜头时长规则、连续性检查、模型、计费单价或实际用量结算。内部标记在 Provider、请求审计和付费单元签名之前移除。

没有 API、数据库、权限、菜单或任务状态契约变更。无需迁移，不包含前端改动及构建产物。

## 离线对比

2026-10-27，本机一次已完成的十集任务共有 45 次逐集生成请求（10 次骨架、35 次分场）。仅在内存中读取其既存请求样本进行转换和引用展开，未再次请求 Provider，未改历史账单或剧本。

| --- | ---: | ---: |
| 35 次分场的系统提示词与正文字符量 | 875139 | 723440 |
| 45 次逐集请求的系统提示词与正文字符量 | 1055034 | 903335 |

分场输入字符量减少 17.33%，逐集阶段整体输入字符量减少 14.38%。这是对完整请求（包含新增引用说明）的离线测量，未计算故事设定、大纲或输出用量。本地 token 估计不是供应商 tokenizer，也不是扣点依据，不可将上述比例直接承诺为实扣降幅。实际费用仍以新请求的供应商用量及原单价结算。

## 验证与运行

从 feature 提交后合入本地 develop，再在本地 develop 的现有 PHP 8.2 容器中执行验证。定向文件清单覆盖上下文、新旧输入契约、请求签名、长篇记忆、场景绑定、对白拆分、时长、分场进度、剧情原文边界、连续性复核、自定义提示词及常规分阶段流程。

新增回归通过实际 ScriptGeneration -> TimedScriptGeneration -> 注入的 Provider 边界捕获请求，比较新旧调用次数、输出、输出预算、系统提示词、完整资料还原和输入估算。回归包含旧契约精确复现、自定义模板、重复 ID 但不同事实、转义路径、JSON 类型、小输入回退、记忆筛选后引用完整性及修复后缀保留。Provider 替身不发送网络或执行扣点。

目录级 PHPUnit 发现既有脚本型测试重复声明 `check()`，因此使用明确的 23 个短剧测试文件清单，不加载其他目录脚本。定向结果：213 tests，通过；最终断言数见本次交付记录。PHP 语法检查及差异空白检查通过。

未执行真实付费生成，因此不将离线输出一致性视为真实模型创作质量的端到端证明。真实效果需观察之后用户正常发起的新任务；已有剧情完整性、场景、时长与连续性检查仍执行。
