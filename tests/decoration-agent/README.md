`DecorationAgentOperations::apply(candidate, operations, scope)` accepts decoded page shape `{data: Widget[], meta: PageMeta[], name, ...unknown}`. It returns `{candidate, changes, image_requests}`. Invalid edits throw `InvalidArgumentException`. Inputs remain unchanged. Model-supplied IDs are ignored for creation; component/list copy receives fresh server IDs. Missing legacy root IDs target `legacy_<sanitized-name>_<index>` without rewriting stored objects for field edits; explicit structural edits materialize stable legacy IDs inside the candidate (selected scope only inside its subtree), preserving identity for subsequent operations. Existing drafts are untouched until apply; nested missing IDs use underscore-separated index paths. Duplicate existing IDs fail safely.

Operations use `type` (`op` is also accepted):

- `add_component`: `name`, optional `content`/`styles` objects or `fields` map of approved dot paths, `children` specifications, `parent_id`, `index`.
- `update_component`: `widget_id`, `fields` map, e.g. `{"content.title":"欢迎","styles.opacity":80,"content.data.0.title":"创作"}`.
- `delete_component`: `widget_id`.
- `copy_component` / `move_component`: `widget_id`, optional destination `parent_id` and `index` (index after removal for move).
- `edit_list`: `widget_id`, `field` (data/fallback_data/areas when registered), `action` (add/update/delete/copy/move), `index`, `row` (`item` alias) or `fields`, `to_index` for move. Existing unknown row fields survive edits; old out-of-editor-limit lists remain editable without increasing their size.
- `configure_page`: optional `name`; `fields` are page-meta content keys, also accepting `content.<key>`.
- `bind_source`: `widget_id`, `source_key`, optional `mode` (source/hybrid/manual) and bounded `params`. Empty source key is allowed in manual mode. Each source has its own parameter allowlist.
- `request_image`: `widget_id`, approved image `field`, `prompt`, `ratio`, `reference_file_ids`. Returns a descriptor including `old_value` and `old_ref` without page mutation; caller authorizes tenant files and generation and compares both the current slot value and its durable reference against `old_value`/`old_ref` before late hydration.
- `replace_page`: `components` is a list of the same name/content/styles/fields/children specifications as add; optional `name` validates the page name. Page/new_page scope only. This explicit operation discards the old component tree.

Scope is `{scope: 'page'|'selected'|'new_page', selected_id?, allowed_links?, approved_urls?}`. Selected scope allows its subtree and refuses root insertion, movement outside it, or page edits. Links must match a trusted available link object; explicit approved external URLs allow only validated HTTP(S) destinations with no credentials. Rich text permits a small formatting-only tag subset without attributes. Image descriptors must target registered image fields. Image writes require a trusted existing/default image URL or an explicitly approved server/user asset URL. Page metadata uses the editor string values for `title_type` and `bg_type`; background video requires an approved URL. The caller must still validate media tenant ownership and prompt policy.

`DecorationAgentMerge::merge(base,current,candidate)` returns `{merged,conflicts}`. It merges disjoint component/object fields and page metadata while preserving unknown extensions. Arrays of content rows are atomic. Conflicting deletion, movement, simultaneous different structure changes, or same-field edits leave the complete current draft intact and report structured conflict reasons. Use `merge(appliedSnapshot,current,baseSnapshot)` for safe rollback; concurrent edits remain protected.

`GET /tenantapi/decorate.agent/stream?run_id=<id>&after=<last-event-id>` uses the existing tenant-admin authentication headers and explicit decoration access/record ownership checks before streaming. Never put authentication tokens in the URL. It is read-only and does not submit/retry tasks. Each `run` frame contains the `run()` snapshot with duplicate cumulative `assistant` events removed from its events list, including `assistant_reply`, `assistant_step` and `assistant_complete`; its SSE ID is the highest durable event ID from the original complete event list, before compaction. Other snapshot fields and execution events are retained. The initial snapshot is always emitted even if `after` is ahead or events have been truncated. Changed snapshots follow at approximately 250 ms polling intervals. Idle connections receive keepalive comments every four seconds. A terminal snapshot emits `done`; an active connection emits `reconnect` after at most 20 seconds. `error` closes a failed read without exposing internal exception details. Reconnect with the last ID; snapshots remain authoritative.

Visible model deltas come only from the root JSON `reply` string. Durable `assistant` events contain cumulative `data.text`, `step`, and `complete`, with writes batched at 250 ms and a final flush. The most recent step reply is retained in run context independently of the event window. Provider reasoning and the operations envelope are never forwarded as reply text. Clarifications persist reply plus question once; advisory final turns with no changes finish without creating a candidate.

Decision validation canonicalizes the engine-supported `op` alias to `type`, preserving explicit `type` precedence and refusing empty/non-string operation names. The real provider page-meta fixture in `decision.php` verifies `content.title` and `content.nav_bg_color` through the actual operation engine. Two occurrences of the same parse error in one run terminate further automatic model rounds; the first records an observation for one correction. Existing billing, uncertain submission handling and tool failure caps remain unchanged.

`php tests/decoration-agent/creation-sources.php` replays the first creation sequences and their following binds from real tutorial/member page runs 36/37 using the sanitized `tests/fixtures/decoration-creation-sources.json`. During creation only, inline `source_key`, `source_params` and `data_mode` declarations pass through the existing `bind_source` validator; direct source updates remain forbidden. A following binding that validates as a complete no-op is skipped before consuming a worker tool slot. No additional operations are synthesized.
